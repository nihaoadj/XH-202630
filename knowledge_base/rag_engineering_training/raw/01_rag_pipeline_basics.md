# RAG 工程链路基础

RAG（Retrieval-Augmented Generation，检索增强生成）通过“先检索、再生成”的方式，让大模型在回答或生成内容时参考外部知识库证据。一个完整的 RAG 工程链路通常包括文档解析、Chunk 切分、Embedding、向量数据库、检索策略、Rerank、Prompt 组装、引用溯源、幻觉控制、评测与调优。

## 核心概念

- 文档解析负责把 PDF、Markdown、网页或 Office 文档转换成可处理文本，并保留标题、页码、章节等元数据。
- Chunk 切分负责把长文档切成适合检索的片段。过大的 Chunk 容易引入噪声，过小的 Chunk 容易丢失上下文。
- Embedding 把文本映射成向量，使系统可以按语义相似度检索。
- 向量数据库保存文本向量和元数据，支持 Top-K 相似度检索。
- Prompt 组装把用户问题、学习者画像、检索证据和输出要求组织成模型输入。

## 常见错误

- 把 RAG 理解成普通问答，忽略证据召回、证据质量和引用溯源。
- 只关注生成效果，不记录检索命中率、知识点覆盖率和幻觉率。
- 忽略学习者能力差异，导致零基础学生拿到过难的调优任务。

## 实操步骤

1. 准备一批 RAG 教学文档，并为每篇文档记录主题和来源。
2. 使用文本切分器按标题、段落和语义边界切分 Chunk。
3. 使用 Embedding 模型生成向量并写入向量数据库。
4. 根据学习主题和薄弱知识点召回 Top-K 证据。
5. 将证据、学习路径和资源类型交给生成 Agent。
6. 用审核 Agent 检查生成内容是否被证据支持。
