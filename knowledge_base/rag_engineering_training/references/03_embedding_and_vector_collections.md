# 权威参考 03：Embedding 与向量集合设计

## Embedding 的职责边界

Embedding 将查询和文档片段编码到同一向量空间，使“措辞不同但语义接近”的文本有机会被相似度搜索召回。它不负责切分、不负责生成答案，也不等同于重排序。若用户问“如何减少胡编”，文档写“用证据约束降低幻觉”，语义向量可帮助两者匹配；能否最终排在前列仍取决于资料、切分、检索策略和重排序。

文档向量和查询向量必须使用兼容的模型、维度和归一化策略。更换 Embedding 模型、修改清洗规则或大幅修改切片策略时，应视为新索引版本，不能与旧向量悄悄混用。

## 集合与元数据设计

一个 collection 应有清晰边界，例如知识库、租户、资料版本或权限域。collection 名称可使用安全的稳定 ID 派生，避免直接依赖中文目录名或用户输入。向量记录至少应包含：

- 稳定切片 ID；
- 文本正文；
- `knowledge_base_id`、`document_id`、标题和来源路径；
- 切片序号、内容哈希、版本或更新时间；
- 可用于过滤的标量元数据。

部分向量库的元数据只接受字符串、数字和布尔值。列表或对象需要在写入边界序列化，并在检索结果返回前还原；否则会出现“模型已编码但写库失败”的隐蔽问题。项目当前对复杂来源元数据进行 JSON 序列化，并在检索时恢复列表结构。

## 相似度与归一化

不同模型可能以余弦相似度、点积或距离作为检索依据。若模型推荐归一化向量，应保证文档和查询采用一致处理；不要将不同模型、不同维度的向量写入同一 collection。分数也不应跨模型直接比较为“置信度”，它更适合作为同一实验配置内的排序信号。

## 质量检查

1. 用同义改写、术语缩写、错误拼写和精确名词分别测试召回。
2. 记录目标片段是否命中、排名位置和相似度分布。
3. 检查重复片段是否占据 Top-K；若是，审查切片重叠和去重逻辑。
4. 更换模型前后必须在同一评测集上比较，不以单个“看起来不错”的答案决定。

## 常见误区

- 把向量分数当作事实正确率：它只表示模型空间中的相近程度。
- 只索引正文、不索引来源 ID：无法进行引用、删除和审计。
- 频繁混用模型写入同一集合：查询维度或语义尺度可能不兼容。
- 将用户私密资料和公共教学资料放入同一无过滤集合：会造成权限和泄露风险。

## 项目落地检查

- 当前中文 Embedding 在 CPU 本地运行，写入与查询使用同一配置。
- collection 以 `knowledge_base_id` 的哈希隔离；资料目录与向量集合可独立重建。
- 文档目录保存完整复杂元数据，向量层只保存可检索、可追溯的副本。
