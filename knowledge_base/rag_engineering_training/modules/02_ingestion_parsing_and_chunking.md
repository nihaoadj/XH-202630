# 综合学习模块 02：资料治理、文档解析与 Chunk 实验

> 本模块将概念教学、入库规范、参数实验和能力检测合并在同一份资料中。
> 主能力节点：文档解析、Chunk 切分。适用层级：零基础、Python 基础。

## 学习目标与阅读路径

学完后应能把 PDF、Markdown、HTML、JSON 等资料转换为可追溯文本，解释清洗与删除的边界，选择切片策略，并通过实验确定 `chunk_size` 和 `chunk_overlap`。初学者先掌握完整入库顺序和失败模式；开发者重点阅读稳定 ID、增量更新和质量验收。

## 1. 入库不是“读取文本然后切几段”

知识库质量上限首先由资料治理决定。若源文件不可靠、版本不明或解析丢失结构，再强的 Embedding 和生成模型也无法恢复缺失事实。完整入库流程应为：

~~~text
登记来源 → 校验许可和版本 → 提取内容 → 结构化清洗
→ 切片 → 质量检查 → 生成稳定ID → 写关系目录
→ 写向量索引 → 抽样检索验收
~~~

原文件、清洗后文档和向量片段应能通过 ID 对应，但不必全部存进同一数据库。

## 2. 来源登记与版本治理

每篇资料建议记录：

- 来源机构、作者、原始 URL、资料类型；
- 获取时间、原始发布时间和适用版本；
- 许可或使用范围；
- 文件哈希与字节大小；
- 解析器名称、版本和处理时间；
- 负责人、审核状态与废弃关系。

URL 不是稳定版本标识，同一网页可能持续更新。关键规范应额外保留发布日期或归档信息。更新时先比较内容哈希，避免无变化资料反复生成新 ID。

## 3. 不同格式的解析重点

### Markdown 与 HTML

保留标题层级、列表、代码块和链接。HTML 应移除导航、Cookie 提示和页脚等模板噪声，但不能把表格、标题与正文错误拼接。片段元数据可保存标题路径，例如“RAG 评测 > 检索指标 > Recall@K”。

### PDF

PDF 是版面描述格式，不天然代表正确阅读顺序。常见问题包括双栏串行、页眉页脚重复、断词、扫描页无文本层、表格列错位和公式丢失。应先判断文本层，扫描件执行 OCR，抽查多栏、表格和代码页，并保存页码与版面块信息。无法可靠解析的表格应保留结构化版本或截图引用，不能拼成错误句子。

### JSON、CSV 与代码

JSON/CSV 适合按对象、记录或业务主键切分，不能每 N 个字符截断。代码优先按文件、类、函数和逻辑块切分，并保留语言、模块与符号名。

## 4. 清洗原则

清洗目标是减少噪声，不是改写事实。可以统一换行和 Unicode、去除重复页眉页脚、修复明显断行，并保留标题、列表、代码和表格边界。不要随意删掉否定词、单位、版本号、条件语句和警告，这些短词往往决定工程结论是否成立。

## 5. Chunk 策略

### 固定长度

实现简单、大小稳定，适合结构很弱的纯文本；缺点是可能从句子、步骤或表格中间切开。

### 递归字符切分

LangChain 推荐通用文本从 `RecursiveCharacterTextSplitter` 起步。它按照段落、换行和空格等分隔符逐级尝试，尽量保留较大语义单元。中文应把句号、逗号、顿号、全角标点和零宽空格加入分隔符，避免依赖英文空格。

### 结构感知切分

Markdown 按标题、HTML 按标签、JSON 按对象、代码按函数切分。通常先按结构得到大块，再对超长块递归切分。

### 语义切分

根据相邻句向量变化寻找主题边界，适合长篇叙述，但成本更高，结果依赖模型和阈值，稳定 ID 也更难维护。没有离线评测时，不能默认语义切分一定更好。

## 6. chunk_size 与 overlap 怎么选

`chunk_size` 要同时考虑 Embedding 有效长度、生成上下文、资料结构和答案粒度。过小会丢失条件，过大会稀释主题并增加 token 成本。

`chunk_overlap` 缓解边界信息丢失，但过大会产生重复召回、挤占 Top-K、提高存储成本，并让评测误以为召回了多个独立证据。

应使用实验选择参数：

| 实验组 | chunk_size | overlap | 关注指标 |
| --- | ---: | ---: | --- |
| A | 小 | 小 | Recall@K、上下文完整率 |
| B | 中 | 小 | 排名质量、答案忠实度 |
| C | 中 | 中 | 边界问题召回、重复率 |
| D | 大 | 小 | 噪声率、token 成本 |

测试集要包含定义题、跨段条件题、列表/表格题、版本题和否定条件题。

## 7. 稳定 ID 与增量更新

文档 ID 不应依赖本机绝对路径。Chunk ID 可由文档 ID、切片序号与内容哈希组合。更新流程要区分：

- 文档未变：跳过；
- 内容变更：重算该文档片段并删除旧片段；
- 文档删除：关系目录和向量 collection 同步删除；
- Embedding 模型变化：建立新索引版本，不能混用不同维度或语义空间。

## 8. 入库质量验收

- 空片段、极短片段、超长片段比例；
- 重复文本和高重叠片段比例；
- 所有片段都有 document_id、chunk_id、标题与来源；
- 标题、代码块、表格和页码抽样正确；
- 典型问题能召回完整定义和限制条件；
- 删除测试能让旧片段真正消失；
- 重复执行入库保持幂等。

## 9. 可执行的中文切片基线

官方文档建议通用文本优先从递归字符切分开始。中文没有稳定的空格词界，因此应把句号、逗号、顿号等加入分隔符。下面是用于实验的基线，而不是对所有资料都适用的固定答案：

~~~python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=100,
    length_function=len,
    separators=["\n\n", "\n", "。", "；", "！", "？", "，", "、", " ", ""],
)

chunks = splitter.create_documents(
    texts=[clean_text],
    metadatas=[{
        "knowledge_base_id": "rag_engineering_training",
        "document_id": "module_ingestion_chunking",
        "source_path": "modules/02_ingestion_parsing_and_chunking.md",
    }],
)
~~~

`chunk_size` 在这里由 `len` 计算字符数，不等于模型 token 数。若下游上下文预算按 token 管理，应另外使用目标模型对应的 tokenizer 统计。分隔符有优先顺序：先尽量保留段落，再保留句子，最后才从任意字符位置截断。代码、表格、公式等结构可能需要专用切分器，不能把这个基线机械套用到所有文件。

## 10. PDF、表格与 OCR 的专项处理

PDF 保存的是页面绘制信息，不保证阅读顺序。双栏论文可能先抽取两栏第一行，再抽取两栏第二行；跨页表格可能丢表头；扫描 PDF 可能没有文本层。建议为每种解析器建立抽样用例：

- 每份文档抽查第一页、随机中间页和最后一页；
- 对标题、页码、脚注、表格、公式和图片说明分别检查；
- OCR 输出保存置信度，低置信度片段进入人工复核；
- 表格切片重复携带表名、列名、单位和时间范围；
- 页眉页脚按跨页重复模式删除，不能用固定行号盲删；
- 原始文件、解析文本和清洗文本分别保留哈希，便于定位损失发生在哪一步。

例如原表格中的“延迟 120 ms”若丢失列名，单独切成片段后无法判断是 P50 还是 P95；若丢失单位，模型可能误解为秒。结构化表格可以先转成“指标=P95 延迟；数值=120；单位=ms；实验版本=v3”的行记录，再参与切片。

## 11. 稳定 ID、版本和增量更新实例

推荐用业务边界与内容共同生成 ID：

~~~text
document_id = hash(knowledge_base_id + normalized_source_path)
content_hash = sha256(chunk_text)
chunk_id = hash(knowledge_base_id + document_id + chunk_index + content_hash)
~~~

只用数组序号作 ID 会产生风险：文档开头新增一段后，后续片段序号全部变化。加入内容哈希可以识别真正改变的片段；但切分参数变化仍会造成大量片段变化，因此每次重建还要记录 splitter 名称、参数和索引版本。

增量更新应按集合差异执行：新 ID 插入，内容哈希改变的 ID 更新，旧版本存在但新版本不存在的 ID 删除。只有插入而没有删除会形成“幽灵知识”，检索仍可能召回已经撤销的规范。

## 12. Chunk 参数实验模板

不要先决定参数再挑示例证明。固定同一批资料、问题、Embedding 和检索算法，只改变切片变量：

| 实验 | chunk_size | overlap | 片段数 | Recall@5 | MRR | 重复上下文率 | P95 延迟 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| A | 300 | 30 | 待测 | 待测 | 待测 | 待测 | 待测 |
| B | 500 | 50 | 待测 | 待测 | 待测 | 待测 | 待测 |
| C | 800 | 100 | 待测 | 待测 | 待测 | 待测 | 待测 |

评测问题至少包含：答案集中在一句内、答案跨两段、需要标题限定、涉及表格、精确编号、无答案问题。若 B 的 Recall 更高但重复率和延迟明显上升，需要结合生成质量与成本决定，而不是只看单个指标。

## 13. 入库程序的防御性检查

在写向量库前阻止以下数据进入：空文本、只有导航字符的文本、超过异常长度的单段、来源缺失、`document_id` 重复但内容冲突、编码替换字符比例过高。写入后验证“计划片段数 = 实际集合新增或更新数”，再随机选择片段执行 `get` 和语义 `query` 双重检查。

失败重试必须幂等。批次写入中途失败时记录批次号与成功 ID，不能重新执行后把同一片段写成多个随机 ID。对于比赛演示，至少展示一次重复入库计数不增长和一次删除旧版本后无法召回的测试。

## 诊断与练习

1. 给定一份包含页眉页脚、跨页表格和扫描图片的 PDF，写出解析、OCR、清洗和抽样验收步骤。
2. 使用同一组问题对比两组 `chunk_size`、`chunk_overlap`，记录 Recall@K、上下文完整性、片段数和索引体积，不能只凭主观阅读选参数。
3. 解释为何去掉所有换行、标题和列表符号会降低可检索性。
4. 验收标准：能发现空文档、乱码、重复片段、孤立标题和缺失来源；重复入库不会制造重复记录；删除旧版本后检索不到旧片段。

### 参考答案与评分要点

- 第 1 题应先判断是否存在文本层，再决定 OCR；按版面恢复阅读顺序，对重复页眉页脚建规则，表格补齐列名和单位，最后跨页抽样。直接“调用 PDF loader”只得少量分。
- 第 2 题必须固定语料、查询、Embedding 和检索算法，只改变切片参数；至少报告 Recall、完整性、片段数和成本。若同时更换模型，实验结论无效。
- 第 3 题要指出结构符号承担语义边界和父级上下文；全部删除后，标题限定、列表归属和段落关系丢失，切片更可能混合不相关内容。
- 建议总分 10 分：解析链路 3 分，受控实验 3 分，结构理解 2 分，幂等与删除 2 分。任何“删除旧版本后仍能召回”的实现不得通过验收。
