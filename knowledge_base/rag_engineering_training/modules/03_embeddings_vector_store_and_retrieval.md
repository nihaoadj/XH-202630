# 综合学习模块 03：Embedding、向量数据库与相似度检索

> 本模块将语义表示、向量存储、Top-K 检索和数据库隔离合并讲解。
> 主能力节点：Embedding、向量数据库、相似度检索。适用层级：零基础、Python 基础。

## 学习目标与阅读路径

学完后应能说明 Embedding 为什么适合候选召回，区分对称与非对称检索，设计 collection 与片段元数据，正确执行写入、查询、过滤和重建。零基础学习者先理解向量和相似度；开发者继续掌握维度、归一化、稳定 ID、权限过滤和版本迁移。

## 1. Embedding 的职责

Embedding 模型把查询和文档编码成固定维度向量，使系统通过向量距离寻找语义接近的内容。它负责候选召回，不负责证明事实正确，也不直接生成答案。

Sentence Transformers 双编码器可分别计算查询和文档向量。文档向量预先存储，查询到来时只编码查询并执行近邻搜索，因此适合大规模第一阶段召回。

## 2. 对称与非对称检索

- **对称任务**：两段文本角色相同，如重复问题检测。
- **非对称任务**：短问题检索长答案或文档，这是 RAG 更常见的情况。

模型如果提供 `encode_query` 和 `encode_document`，应分别用于查询与语料，保留模型设计的 prompt 或任务标记。不能默认所有通用语义相似度模型都适合问答检索；模型卡、训练语言、最大长度和检索基准都需要核对。

## 3. 相似度与归一化

常见度量包括余弦相似度、点积和欧氏距离。若向量做了 L2 归一化，余弦相似度与点积排序存在直接关系；未归一化时，向量模长会影响点积分数。

工程上必须固定并记录：

- 模型名称和精确 revision；
- 向量维度；
- 是否归一化；
- 查询与文档的编码方式；
- 向量库距离函数；
- 分数方向：越大越相关还是距离越小越相关。

更换其中任何一项都可能使旧阈值失效。禁止把不同模型生成的向量写进同一索引空间。

## 4. 批量编码与异常处理

大批量入库要监控批量大小、CPU/GPU 内存、最大 token 长度和失败重试。超长文本可能被模型截断，因此“字符数未超限”不等于“模型 token 未超限”。

入库报告应保存文档数、片段数、成功/失败数、截断数、编码耗时、向量维度、模型版本和索引版本。出现 NaN、维度不一致或空文本时应拒绝写入，不能跳过后继续形成不完整索引。

## 5. Collection 是隔离边界

Chroma 的 collection 是存储和查询的基本单元。不同知识库使用独立 collection，可降低误检、删除和版本管理风险。collection 名称由稳定 `knowledge_base_id` 映射生成，元数据记录知识库版本、Embedding 模型和创建时间。

打开已有 collection 时应验证配置兼容性；不能仅凭名称相同就假设维度和编码方式一致。

## 6. 写入字段与幂等

每条向量记录至少包含稳定 `chunk_id`、正文、`knowledge_base_id`、`document_id`、`chunk_index`、标题、来源、知识点、内容哈希、文档版本及必要权限。

稳定 ID 配合 upsert 能让重复入库保持幂等。生产更新不应先删除全部旧索引；可以构建新 collection，校验完成后再切换。

## 7. query、get 与元数据过滤

Chroma `query` 执行近邻搜索，`get` 按 ID 或过滤条件读取记录，不做相似度排名。查询可以传文本或预先计算的向量，向量维度必须与 collection 一致。

`where` 用于元数据过滤，`where_document` 用于文本条件。过滤可实现知识库、租户、版本、时间、语言、难度、知识点和权限隔离。过滤过严会造成召回为空，所以每次查询要记录实际过滤器，并区分“被过滤为空”与“语义检索失败”。

项目使用的 Chroma 版本可能只接受标量元数据。若上层存在列表或对象，应在写入边界兼容序列化，在读取时恢复；升级后再依据目标版本官方能力决定是否直接使用数组。

## 8. Top-K 与阈值

Top-K 决定候选数量，不代表前 K 条一定相关。K 太小会漏召回，太大会把噪声带给生成器。相似度阈值也不能跨模型照搬。

合理流程：

1. 用标注查询统计相关片段排名分布。
2. 选择满足目标 Recall@K 的候选 K。
3. 用重排器压缩到较小最终 K。
4. 对低置信查询执行拒答、扩大候选或查询改写。

阈值必须从验证集产生，并按知识领域和查询类型监控。

## 9. 安全和运维

- 删除文档时同步删除向量、目录和缓存。
- 不把本机绝对路径返回前端。
- 权限在检索前过滤，不能召回后再要求模型保密。
- 监控 collection 数量、向量数、索引大小、延迟和空召回率。
- Embedding 升级采用可回滚的新索引版本。

## 10. 相似度计算与分数方向

设查询向量为 q，文档向量为 d。余弦相似度为：

~~~text
cos(q, d) = (q · d) / (||q|| × ||d||)
~~~

若向量已经进行 L2 归一化，余弦相似度就等于点积。欧氏距离则计算向量差的长度。相似度通常越大越近，距离通常越小越近；不同库的 API 可能返回相似度、距离或经过转换的 relevance score，必须阅读接口定义并通过已知样本验证。

简单例子：归一化查询 `q=(1,0)`，候选 `d1=(0.8,0.6)`、`d2=(0,1)`。二者范数均为 1，`cos(q,d1)=0.8`，`cos(q,d2)=0`，所以 d1 更相似。若系统返回的是余弦距离 `1-cos`，则 d1 为 0.2、d2 为 1.0，此时较小值更好。把这两种分数方向弄反会让最差片段排到最前。

不要把不同模型生成的向量放进同一索引。即使维度相同，它们的空间含义也不同；维度不同通常会直接报错。模型升级应创建新索引版本，全量编码并在固定评测集上比较，再切换别名或业务配置。

## 11. 查询与文档编码的选择

语义检索模型可以针对对称或非对称任务训练。问答检索属于“短问题找长答案”的非对称任务，支持时应分别使用查询与文档编码入口，例如 `encode_query` 和 `encode_document`；重复问题检测属于对称任务，可以使用相同编码方式。

选模型时至少登记：模型名称与修订版本、向量维度、最大输入长度、是否适合中文、是否要求前缀、归一化设置、推理设备、批大小和许可证。只比较公开榜单不够，还要在本项目问题上测 Recall@K、延迟、内存和索引体积。

长片段超过模型最大输入长度时可能被静默截断，造成片段后半部分从未进入向量。入库程序应记录 token 长度分布和截断数量；若截断率高，应先调整切片，而不是期待向量模型理解没有看到的内容。

## 12. Chroma 写入与过滤示例

下面展示底层 collection 的核心操作。项目可以通过 LangChain 封装，但业务字段和过滤边界不应丢失：

~~~python
collection.upsert(
    ids=["chunk_a", "chunk_b"],
    documents=["第一段证据", "第二段证据"],
    embeddings=[embedding_a, embedding_b],
    metadatas=[
        {"knowledge_base_id": "rag_engineering_training", "level": "零基础"},
        {"knowledge_base_id": "rag_engineering_training", "level": "进阶 RAG"},
    ],
)

result = collection.query(
    query_embeddings=[query_embedding],
    n_results=5,
    where={"knowledge_base_id": "rag_engineering_training"},
    include=["documents", "metadatas", "distances"],
)
~~~

Chroma 的 `where` 用于元数据过滤，`get` 用于按 ID 或条件读取记录，`query` 用于近邻检索。业务层应区分二者：审计页面按 `chunk_id` 精确打开证据时用 `get`，回答问题时才用 `query`。权限字段必须作为过滤条件进入查询，不能仅依赖 Prompt。

## 13. Top-K 与阈值的校准

Top-K 控制最多返回多少候选，阈值控制候选至少多相似。只用 Top-K 时，即使所有片段都不相关也可能硬返回 K 条；只用严格阈值则可能在表达差异大时空召回。建议先用 Top-K 得到候选，再依据验证集校准阈值，并保留“无候选”分支。

校准步骤：

1. 标注一批问题与相关片段；
2. 保存所有候选的原始距离、排名和相关标签；
3. 绘制相关与不相关候选的分数分布；
4. 在可接受漏召回率下选择阈值；
5. 按问题类型分别查看，精确编号与抽象概念可能需要不同策略；
6. 模型或索引版本改变后重新校准，不能沿用旧阈值。

假设 Top-5 中前三条相关，后两条不相关，提高阈值可能改善上下文纯度；但若唯一正确片段恰好排第五，提高阈值会让生成器完全失去证据。因此阈值必须结合 Recall 与最终 groundedness 共同决定。

## 14. 索引迁移与回滚流程

生产环境不要原地覆盖正在服务的集合。创建带版本的新 collection，后台全量编码，核对文档数、片段数、维度、抽样查询和离线评测；通过后把业务配置切到新版本，并保留旧版本一段观察期。若空召回率、延迟或质量异常，立即回切。

迁移记录至少包含旧/新模型、旧/新集合、切片版本、开始和完成时间、写入数量、失败 ID、评测报告与批准人。这样“模型升级后回答变差”才有可定位和可恢复的路径。

## 诊断与练习

1. 判断场景属于对称还是非对称检索，并说明为何查询和文档可能需要不同编码方法。
2. 为一个多课程知识库设计 collection、`document_id`、`chunk_id`、版本、来源和权限字段。
3. 对同一查询比较 Top-3、Top-5、Top-10 的相关片段比例与漏召回情况，说明为何 Top-K 不是越大越好。
4. 验收标准：能解释距离分数方向，能排查维度不一致、重复写入、空召回和跨知识库串数据，能证明权限过滤发生在生成之前。

### 参考答案与评分要点

- 第 1 题中，重复问题属于对称检索；短问题找长文档属于非对称检索。后者若模型支持，应分别编码查询与文档，因为两侧语言分布和任务角色不同。
- 第 2 题应以知识库作为 collection 或等价隔离边界；`document_id` 绑定来源路径，`chunk_id` 结合片段序号与内容哈希；元数据含版本、来源、能力节点和权限。
- 第 3 题要同时报告相关数量和比例。Top-K 增大可能找回遗漏证据，也会引入噪声、重复内容、token 与延迟成本，不存在通用最大值。
- 建议总分 10 分：编码任务 2 分，数据模型 3 分，Top-K 实验 2 分，分数/维度/权限排障 3 分。无法说明分数方向时不能进入阈值调优。
