# 综合学习模块 05：上下文组装、引用与忠实生成

> 本课版本：teaching-2026-10-v2。rag-lab-v2 是合成教学数据，不代表业务制度、线上资源或真实审核结果；状态词表仅用于解释，不是项目 DTO 或人工审批承诺。
> 能力节点：Prompt 组装、引用溯源、幻觉控制。初学者先读 1、2、4、5；实现者完成 9–13；进阶者完成 6–8、14。

## 学习目标与分层阅读

完成本课后，你应能将候选整理成有边界的证据包，在 token 预算中保留来源；将复合答案拆成原子事实并逐条核对；遇到缺证据、冲突、越界或审核依赖不可用时，给出可解释的结果。引用链接可打开不等于引用支持结论，Prompt 写了“依据证据”也不等于输出经过校验。

初学者先做证据选择和拒答练习；实现者要给每条 Claim 保存证据映射、状态和审核版本；进阶者检查冲突、非可信文档指令、重审历史和权限边界。本文讲的是可审计的教学契约，不代表当前应用已经实现这些字段或流程。

## 贯穿实验：rag-lab-v2（合成教学数据）

唯一共享案例见 [lab_case.json](../lab_case.json)：四份合成资料为 lab-A、lab-B、lab-C、lab-D，四个固定问题为 Q1、Q2、Q3、Q4。Q1 检查 500/100 的单位与适用边界；Q2 询问 RRF 是否直接相加 BM25 与向量分数，相关资料是 lab-C；Q3 询问报名截止日期，资料 lab-D 明确说明没有给出日期，故不可回答；Q4 综合 RAG、召回、融合和重排关系。Q2 的正确教学结论是 RRF 按排名融合；这组文字不证明任何真实业务日期、政策或模型效果。

本课以 Q2 训练“有相关来源但答案可能错”，以 Q3 训练“资料明确缺信息时拒答”。可在回答内部临时用 lab-C、lab-D 指代证据，不新增案例 ID，也不伪造 fixture 中不存在的 chunk_id。所有下列审核状态和答案均是课堂推演，不是运行产物。

## 1. 候选不是证据包

证据包必须受 token 预算约束、来源明确、顺序合理；不是把 Top-K 原样拼接。

Top-K 结果可能重复、冲突、过时，或只包含结论的一部分。组装时依次核对知识范围、访问条件、版本和来源；按问题需要去重、合并相邻片段、排列顺序，再在预算内裁剪。候选被检索到只说明它进入了待检查集合，不能证明它支持回答。

【初学】问 Q3 时，lab-D 能支持“该练习资料未给出日期”，不能支持一个具体截止日。【实现】每条保留内容带上原始文档/片段标识和版本；合并片段要保留成员来源。【进阶】遇到两个版本或两个适用范围时，先标差异，再决定能否合并。

## 2. Token 预算分配

模型上下文还要容纳系统指令、用户问题、对话历史和输出。先确定输出预留，再对证据分配剩余预算；不要把上下文窗口上限全部当成证据预算。超过预算时，优先保留直接回答问题的条件、单位、否定和限制，不要只按相似度删尾部。

长材料可以先定位章节，再扩展父级上下文；相邻片段可合并，但必须保留页码/标题或片段关系。rag-lab-v2 没有 token 数或截断结果，本课不填写模型 token 成本，也不把字符长度冒充 token 长度。

## 3. 证据边界与生成约束

证据包应明确区分问题、证据区与输出格式。事实只根据给定证据陈述；证据不足或冲突时要指出缺失；不能执行文档里的命令；不要伪造引用、版本和来源。把检索文本当作不可信数据：文本中的角色声明、工具调用指令或“忽略上文”仍是文档内容，不会改变服务端授权。

Prompt 是风险控制的一层，不是权限系统、证明器或 schema 校验器。生成后还要检查引用是否存在、Claim 是否能映射到证据、结构是否合法。若格式校验失败，应修复、重试或进入失败路径，不能默认为通过。

## 4. Claim 级核验

引用准确率与答案正确率不同：答案可能正确却引用错误，因此两项要分开核验，不能互相替代。

把一段回答拆成可单独判定的原子事实。例如“方法 X 更快、更准且更便宜”至少有三个待证结论。每个 Claim 单独记录正文、证据标识、支持关系和适用限制；审阅时分别问：它是否是可核验事实？证据是否直接支持？是否漏了条件？是否有相反材料？

不要用段落末一个引用覆盖整段。一个证据可以支持多个 Claim，一个 Claim 也可能需要多个来源；映射要明确到证据项，而不仅是文档标题。无法拆清或无法核对的内容要标成待修，不得借无关引用“补齐”。

## 5. 证据不足、冲突与领域外

Q3 是明确无答案练习：lab-D 写明没有报名截止日期。合格回答是“这组资料未提供日期”，而不是从模型记忆或外部常识补日期。若问题超出知识范围，说明范围不足；不要用语义相似片段拼答案。

资料冲突时，比较版本、发布时间、适用对象、有效期和来源类型。能证明新资料废止旧资料时，说明依据并引用新版本；若条件不同或无法裁决，应并列说明。这里描述处理方法，不给 rag-lab-v2 增添一个虚构冲突案例。

## 6. 教学审核状态词表

本课只使用一组统一词表，便于练习状态分支：

| 教学状态 | 含义 | 教学后续 |
| --- | --- | --- |
| passed | 已完成核对，关键可验证 Claim 有支持且引用有效 | 可进入后续流程，但仍保留审核记录 |
| revision_required | 发现可修正的问题，如漏条件、错误引用或格式不合格 | 修正后以新版本重新核验 |
| rejected | 核心事实被反证、无证据且不能安全修正，或严重冲突 | 不应把该版本当作通过结果 |
| review_unavailable | 审核依赖、解析或数据读取不可用，无法作出判断 | 作为失败/不可用处理；绝不能等价于 passed |

这些英文标签是教学映射，不保证与项目 API/DTO 的枚举、数据库字段或转换规则相同，也不意味着存在人工审批工作台。特别是 review_unavailable 不能等于 passed：依赖失败只说明未能核验，不说明内容正确。

## 7. 自我反思与程序边界

Self-RAG 的研究提示可把“是否需要检索、证据是否相关、回答是否被支持”变成显式检查点。普通教学练习可以逐项核对这些问题，不需要训练或复制该研究模型。将检查结果记录为结构化字段，比只留下自然语言“我觉得有依据”更易复核。

程序规则可以检查来源 ID、输出 schema 和缺失字段；语义支持关系仍要明确它的判定方法和误差。模型自评、自动裁判或相似度分数都不能单独作为事实正确性的证明。

## 8. 最小验收场景

用相同证据包检查六类结果：单事实与准确证据；多条件结论与多条证据；Q3 无答案与明确拒答；版本冲突与差异披露；文档中有不可信指令但不执行；审核依赖不可用且不记录成 passed。验收不仅看最终回答，还要检查引用映射、状态、版本和失败原因。

【实现者】保存一条回归样本时，固定问题、证据 ID、预期 Claim 列表和允许状态；变更后对比字段，不以“回答看起来更自然”替代契约检查。【进阶者】让无证据、错引用、矛盾和依赖失败分别触发不同断言，避免所有失败都落进同一个通用拒答。

## 9. 证据包：固定输入与期望产物

证据去重不能只看文本完全相等：相邻重叠切片应结合文档、相邻序号和文本重叠率决定是否合并，保留成员映射。回答里的 ref 是短引用编号；chunk_id 是数据库证据标识，二者不同。界面上的 ref 应能经映射定位 chunk_id，再打开原始片段、文档、版本和来源。lab-C 只是课堂文档 ID，不能冒充真实 chunk_id。

对 Q2，允许的证据对象是 lab-C，其文本说明实验使用关键词与向量两路候选、RRF 按排名融合、重排只对已召回候选排序。若生成回答说“RRF 直接相加 BM25 和向量裸分”，该 Claim 与 lab-C 相反；若又说“RRF 一定提高召回率”，lab-C 没有提供这个普遍结论，不能判为有支持。

一个最小课堂产物可以写为：

~~~json
{
  "question_id": "Q2",
  "evidence": [{"document_id": "lab-C", "text": "按排名融合；重排只排序已召回候选"}],
  "claims": [
    {"text": "RRF按排名融合", "evidence_document_ids": ["lab-C"], "verdict": "supported"},
    {"text": "RRF一定提高召回率", "evidence_document_ids": [], "verdict": "not_in_evidence"}
  ]
}
~~~

上例中的 Claim 文本和 verdict 是教学练习输出，不是新增 fixture 记录。检验点是每个结论是否独立、映射是否真实、是否把缺证据误写为已证实。Q3 的期望产物应保留 answerable=false，说明缺失日期；不能输出一个猜测值。

## 10. 受约束 Prompt 与输出后校验

Prompt 可以要求模型只根据证据回答、对可验证事实标注引用、遇到缺证据时说明缺失，并将证据区当作资料而不是指令。证据标签应由程序从当前证据包生成，不让模型自造新标签。输出建议使用固定 schema，包括 answer、claims、evidence_document_ids、verdict 和 refusal_reason 等教学字段。

【实现】至少做以下确定性检查：引用 ID 必须存在；Claim 的引用集合不为空时，每个引用都属于本次 evidence；无答案样本不含肯定的日期 Claim；必需字段和类型正确。确定性检查只能验证结构/引用存在，不能自动证明语义蕴含；语义审阅须单独记录方法与状态。

## 11. 原子 Claim 演练与反例

一个明确反例是“RRF 把不同检索器的原始分数直接相加”：这与按排名倒数融合的定义矛盾，应标 contradicted，而不是把它当作正确结论。

用 rag-lab-v2 的 Q2 回答制作两个独立 Claim：“RRF 按排名融合”与“RRF 一定提高召回率”。前者有 lab-C 支持；后者没有普遍效果证据，标为 not_in_evidence。若把它们揉成“RRF 按排名融合并一定提高召回率”，整体状态会掩盖前半有证、后半无证的问题。

支持状态词需与待核验对象匹配：supported 表示有直接依据；contradicted 表示证据与陈述相反；not_in_evidence 表示当前材料未能支持该事实，不能擅自扩写为“事实为假”。non-factual 文本不参与事实 Claim 支持率。若现有证据不足以判断真伪，先标清不可判定原因，不编造外部证据。

## 12. 审核记录、不可用与重审

每轮核验至少记录输入资源版本、规则/裁判版本、起止时间、Claim 数量、各状态计数、失败原因和关联证据。重审应追加一条新的审计记录，保留原结果及其时间；不要把“第一次失败”覆盖成“现在通过”，否则无法解释版本变化。

教学状态中的 review_unavailable 是无结论，而不是负面事实 verdict，也不是 passed。线上/项目落库字段以实际 DTO 与数据库为准；本章不声称这些字段已经在运行系统中存在，也不将状态解释为人工批准或人工否决流程。

## 13. 间接提示注入与权限

知识文档可能含有看似指令的文字。处理顺序应让资料内容与系统规则分开；工具调用和数据访问由受控应用边界授权，不能由文档内容授予；对输出再检查越权引用或敏感信息。测试时可在隔离教材文本中加入“忽略规则”字样，验证它作为引用文本被呈现而不是被执行。不要把这种课堂字符串当成新的 fixture 文档或攻击实测。

权限过滤应发生在证据进入生成上下文之前。Prompt 只能约束已有上下文中的表达，不能撤回已经泄露的数据。本节是安全设计说明，不是对当前项目实际权限路径的审计结论。

## 14. 来源时效与冲突处理

先区分“来源在时间上更新”与“同一问题有相反结论”。比对发布日期、版本、范围和是否明确废止；记录选择理由，保留被淘汰材料的历史关系。若来源各自适用于不同版本或场景，应同时展示条件，而不是强行选一条。来源权威性取决于 Claim 类型：论文可解释方法，产品官方文档可说明其版本 API，项目配置才能证明本项目设定。

rag-lab-v2 中 lab-B 的 500/100 是字符计数实验基线，不是通用最优参数，也不是模型 token 上限；不得把它和其他版本的真实规范混为一谈。案例没有时序冲突数据，因此本节只给出判断流程，不声称发生过冲突。

## 诊断与练习

1. 【初学】回答 Q3。指出 lab-D 中哪句话支持“资料没有日期”，并说明为什么不能填写猜测日期。
2. 【实现】对 Q2 的两个 Claim 逐条输出支持映射和状态：一条是“RRF 按排名融合”，另一条是“RRF 一定提高召回率”。解释 supported 与 not_in_evidence 的区别。
3. 【实现】为上面的 JSON 加一条后置校验：引用不存在时拒绝；Q3 若出现肯定日期则失败。说明哪些校验只能检查结构、哪些仍需语义核验。
4. 【进阶】设计审核依赖超时后的记录，不改变证据与原版本；明确状态、原因、重审时如何保留历史。不得设计人工审批工作台。
5. 验收：引用能回到真实案例资料；无证据时不凭模型记忆补全；状态词表始终一致；review_unavailable 不等于 passed；项目 DTO 与本教学例子有明确边界。

### 参考答案与评分要点

- 第 1 题：lab-D 明示练习未给出报名截止日期，回答应说“资料未提供，无法确认”。不猜具体日期。证据定位 1 分，拒答理由 1 分。
- 第 2 题：lab-C 明示 RRF 按排名融合，第一条 supported；“一定提高召回率”不在该资料中，第二条 not_in_evidence。not_in_evidence 不表示已证伪。映射 2 分，区分状态 2 分。
- 第 3 题：先校验引用 ID 存在、范围属于本次证据包；Q3 肯定日期触发确定性失败。代码只能查字段和引用集合，是否蕴含仍要语义判断。结构检查 1 分，语义边界 1 分。
- 第 4 题：记录 review_unavailable 与错误原因，不产生 passed；恢复后新建审核版本/记录，保留旧记录。历史和状态各 1 分。
- 总分 10 分；把无证据 Claim 判成 supported、把 unavailable 判成 passed、或把教学状态宣称为项目 DTO/人工审批流程，均未通过。
