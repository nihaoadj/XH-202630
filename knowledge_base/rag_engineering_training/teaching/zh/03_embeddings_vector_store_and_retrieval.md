先修为模块02的来源、切片和活动版本。继续使用[rag-lab-v2数据](../lab_case.json)：Q1→lab-B，Q2→lab-C，Q3没有日期，Q4需要lab-A与lab-C。这里不额外编一套“模型正确率”来代替实验。

## 1. Embedding 的职责

Embedding把文本映射为固定维度向量，供候选召回使用。它不直接生成答案，也不负责证明事实正确。[S1，Background] 查询向量与文档向量的相似关系只是任务表示，不能当成来源权威性、时效或事实支持程度。

以Q1为例，“500”和“100”都出现在lab-B，但用户还问单位与是否最优。模型若只对数字相近的片段打高分，答案仍可能丢掉“字符”“本实验”和“不是通用最优”。检索结果必须回到原文检查。

可把职责分成三问：Embedding问“哪些片段值得看”，重排问“已召回候选哪个更相关”，证据审核问“具体结论是否被支持”。三者需要不同输入和评价，不能因为某个分数高就省去后两步。

## 2. 对称与非对称检索

对称任务两侧角色近似，例如重复问题检测；非对称任务常是短问题检索长解释，直接交换两侧往往不合理。[S1，Symmetric vs. Asymmetric Semantic Search]

模型支持时，问答检索应使用其约定的encode_query和encode_document，并保留要求的前缀或任务标记。并非所有模型都必须使用不同方法；如果模型没有相应prompt或任务路由，接口名称不同也可能得到相同表示。按具体模型文档决定，而不是照抄函数名。

课堂Q2可以写成中文原问，也可以写英文检索表达“Does RRF add raw scores?”。它们目标相同，但表达方式不同；这只是待检验的查询对，不是“多语言模型必能检索成功”的证明。

## 3. 相似度与归一化

需要固定的不是一个模型名，而是一份编码契约：精确revision、维度、归一化、查询/文档编码方式、输入长度策略、距离度量和分数方向。相同名称可能有不同revision，相同维度也不证明向量空间兼容。

禁止把不同模型生成的向量写进同一索引空间，即使维度相同。换模型、归一化或查询前缀后，旧阈值与排名分布也可能失效；仅让写入API不报错并不等于可以混用。

本章二维数值用于手算，不由任何Embedding模型产生。真正评测还需固定语料和相关性标签，不能拿这个例子宣布当前模型更准。

## 4. 批量编码与异常处理

实际编码要关注批量、设备内存、token长度分布、截断和重试。空文本、NaN或维度不一致应在写入前拒绝，并记录失败ID，不应悄悄跳过后仍发布“完整索引”。

字符长度与token长度不同。同样500字符，中英文和代码可能产生不同数量的token；保留一个长代码块的全部文字，不表示模型实际看到了全部内容。截断检查由模型对应tokenizer和输入配置决定，不是从len猜一个精确值。

本次练习不加载tokenizer或模型，所以token_count、embedding_latency等字段标为not_measured，不填0或虚构数。0意味着测得为零，不是“尚未测”。

## 5. Collection 是隔离边界

Chroma的collection是存储与查询的基本单元。不同知识库使用独立collection能降低误检与误删除风险，但collection本身不是完整授权系统。租户、知识版本和模型空间需要由应用明确绑定。

打开已有集合时要核对模型/维度/度量与版本，不能仅凭名称一致复用。把新模型向量写到旧集合，即使没有维度错误，仍可能得到语义不可比的排名。

本地、服务端和Cloud部署有不同能力与运维方式。[S3，Initialization] 官方Cloud教程里的功能不能直接视为当前本地依赖已支持；“本项目用Chroma”也不代表所有教程代码能原样运行。

## 6. 写入字段与幂等

建议记录chunk_id、正文、知识库/文档/内容版本、来源位置、知识点、哈希和必要过滤字段。稳定ID配合upsert可以避免同一内容重复写出多个随机记录；它不意味着允许相同不可变版本ID被任意改写。

生产更新不应先删全部正在服务的旧索引再重建。可以创建新collection，验证完整性和质量后切换；历史版本按回滚与审计策略处理。这里是目标设计，不宣称当前项目已经实现影子索引切换。

如果旧SQL保存的是另一套路径metadata，单清空Chroma不能解决SQL版本冲突。必须决定新知识身份或受控目录迁移，再让关系目录和向量集合对应。本仓库目前尚待后续换模重建，本章不会执行该操作。

## 7. query、get 与元数据过滤

按Chroma接口语义，query用于近邻搜索，get按ID或条件读取、不进行相似度排名；where过滤元数据，where_document过滤正文内容。[E1] LangChain封装常使用filter等不同参数名，不能把封装层与底层参数混写。

每次查询应保存真实过滤器，并区分“权限/版本过滤后为空”和“语义检索没有相关证据”。对于Q4，如果可见资料只有lab-A、lab-B，lab-C不能因为相关就越权加入；这时完整解释证据不足，不是靠提高K补齐权限。

精确按ID打开证据不等于检索质量测试。get只取正文/元数据时可能没有覆盖底层近邻索引的加载路径；因此需另测query及重启后的可用性。具体存储细节随版本变化，不能把一次本地现象当成所有版本的接口保证。

## 8. Top-K 与阈值

Top-K限制候选数量，不承诺这K条都相关；阈值是一种筛选规则，不是正确概率。若Q3没有日期，多返回几条RAG文档也不能让问题变得可回答。

先根据标注看Recall@K，再依据上下文预算与排序选择最终证据数。召回候选K与生成上下文K必须区分：前者为正确证据争取进入后续的机会，后者控制最终输入的噪声与成本。

阈值需从验证集产生，不能跨模型照搬。例如距离越小越近时的“最大允许距离”，与相似度越大越近时的“最低相似度”不等价。§10先用手算明确方向，§13再讨论校准，不在两处重复模型定义。

## 9. 安全和运维

检索前的权限过滤是服务端边界，不能先召回其他用户资料再靠Prompt要求模型保密。删除当前文档需同步失效活动目录、向量与缓存；历史证据保留政策另行规定。

监控向量数量、空候选、延迟、失败ID和版本，但不要把本机绝对路径或密钥放入用户结果。审计记录能证明哪批数据参与了查询，不自动证明答案事实正确。

课堂只在四份合成资料上演练允许集合，不生成真实用户权限，不修改项目数据库。教学脚本中的allowed集合只是示意，不能当作生产授权实现。

## 10. 相似度计算与分数方向

令q=(1,0)，d1=(0.8,0.6)，d2=(0,1)，三个向量范数都是1。余弦相似度cos(q,d1)=0.8，cos(q,d2)=0，所以d1更近；余弦距离1−cos分别为0.2、1.0，方向反过来。

~~~python
from math import sqrt

def cosine(a, b):
    if len(a) != len(b):
        raise ValueError("dimension mismatch")
    na, nb = sqrt(sum(x*x for x in a)), sqrt(sum(x*x for x in b))
    if na == 0 or nb == 0:
        raise ValueError("zero vector")
    return sum(x*y for x, y in zip(a, b)) / (na*nb)

q, d1, d2 = (1, 0), (0.8, 0.6), (0, 1)
assert abs(cosine(q, d1) - 0.8) < 1e-12
assert cosine(q, d2) == 0
~~~

L2归一化后余弦相似度与点积相等；未归一化时模长会影响点积。这个手算不能说明d1对应的文字是真的，也不能把0.8解读为80%正确。分数方向弄反会把差候选排在前面，应该用已知向量和重复文本先做检查。

## 11. 查询与文档编码的选择

先核对任务和语言，再谈模型大小：查询是中文、语料是中文/英文/代码的哪些组合？是否需要特定前缀？最大输入长度如何定义？模型和数据的许可是否匹配？本地BGE官方说明列出了不同语言的模型与查询指令，[S2，模型列表] 不能只见“BGE”三个字就认为配置相同。

跨语言实验应分别记录“中文问中文”“中文问英文”“英文问中文”的相关标签和排名，避免平均分掩盖一个方向很差。Q2的中英文表达可作为课堂输入设计，但本次没有编码，所以不提供这些方向的真实Recall。

超长文本可能被静默截断，片段后半部分从未进入向量。先检查token长度与截断数量，再考虑切片或模型；不能期待模型理解没有读到的条件。模型选型、权重下载和实际重编码属于后续工作，本章不执行。

## 12. Chroma 写入与过滤示例

以下是概念性调用骨架，不是可直接运行的项目代码；collection、embedding和权限策略必须由正确版本的适配层提供：

~~~text
upsert(
  ids = 已验证稳定chunk ID,
  documents = 同版本正文,
  embeddings = 同一模型空间的向量,
  metadatas = 知识库/文档版本/可授权过滤字段
)
query(
  query_embeddings = 同契约的查询向量,
  n_results = 召回候选K,
  where = 服务端生成的允许条件
)
get(ids = 最终证据ID)  # 精确回读原记录，不做相似度排序
~~~

在不调用任何模型的课堂版中，可先演练过滤顺序：

~~~python
allowed = {"lab-A", "lab-B"}
constructed_candidates = ["lab-C", "lab-A", "lab-D", "lab-B"]
visible = [ident for ident in constructed_candidates if ident in allowed]
assert visible == ["lab-A", "lab-B"]
~~~

这些候选是人为构造，不代表真实召回。过滤后看不到lab-C，应记录证据受限，不允许模型把它从记忆中补回来。真实系统应在召回边界就限定允许范围，上述列表例只帮助检查结果，不替代数据库侧权限控制。

## 13. Top-K 与阈值的校准

校准需要问题、相关证据集合和候选原始分数，而非只保存最终回答。按问题类型画相关与不相关候选分布，分别看漏召回、噪声、正确拒答和错误拒答。

模型或索引版本改变后必须重新校准；不能沿用旧阈值。只用Top-K可能在全不相关时仍返回K条，只用严格阈值也可能丢掉唯一正确证据。阈值、候选K、最终证据预算要一起解释，不能拿一个漂亮平均值代替。

ANN索引还可能有近似搜索误差，速度与召回存在取舍。[S1，Approximate Nearest Neighbor] 若原始相关文档在库内却始终没进入候选，先对照精确搜索或关键词基线，别直接归咎于生成器。

## 14. 索引迁移与回滚流程

换模型前冻结资料、切片器、查询标注和旧版本身份；为新空间创建新集合，批量编码并校验维度/记录/来源/查询；通过后才切换，保留可工作的旧版本作为回滚依据。坏索引的文件备份仅保留现场，不等于可用回滚。

本仓库直接移动资料后，旧SQL仍保存旧路径metadata。未来重建要使用隔离的新knowledge_base_id、版本化文档身份或明确SQL迁移策略，而不是只提高metadata.version；同内容和同ID仍可能触发不可变版本校验。这是当前工程边界说明，不是本轮新增功能。

迁移验收应包含新进程实际query；仅比较count或健康接口不足以证明所有片段可检索。真实模型质量还需固定查询评测，本章只教检查方法，不给未经测量的提升承诺。

## 贯穿实验：交付一份不编码的索引检查清单

**输入**：rag-lab-v2四份短文、Q1–Q4、§10二维向量，以及§12构造候选与allowed集合。

**步骤**：手算并运行纯标准库余弦函数；标清相似度/距离方向；写一份模型契约模板，把未知模型revision和token统计标not_measured；根据权限允许集合审查Q4是否有完整证据。

**期望产物**：d1相似度0.8、d2为0的手算记录，未使用模型的声明，一份字段齐全但不伪造数值的索引检查清单。Q1需要lab-B；Q2需要lab-C；Q3不得编日期；受限Q4不能声称证据齐全。

**失败排查**：把距离降序排了，先改方向；维度不等，拒绝进入计算；过滤为空，先查允许范围；索引字段不齐，不用猜测revision补洞。这里不会建立collection或下载任何权重。
