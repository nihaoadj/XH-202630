> 教学修订：teaching-2026-10-v2。主节点：RAG 基础概念。
> 案例版本：rag-lab-v2。案例、排名与输出都是合成教学数据，不是真实业务制度、线上结果或模型实测。

## 学习目标与分层阅读

- **入门**：先读§1、§2、§5和贯穿实验，能区分“找到资料”和“正确回答”，画出离线、在线两条链。
- **实现**：读§4、§6–§9，能检查证据身份、版本、分数及错误归属，交付一份可复核的trace。
- **进阶**：读§3、§10、§11，理解检索模型与生成模型的不同职责，并讨论权限、拒答和组件替换边界。

先修只要求能阅读短文本与简单JSON，不要求安装模型。后续模块会分别完成切片清单、索引检查、融合排序、Claim审核和评测报告。不要把这六项工作混成一次“大模型调用”。

## 1. RAG 解决的核心矛盾

大语言模型把训练中的知识模式存入参数。它可以组织语言，但业务资料的更新、删除和逐条追溯不等于修改一次提示词。RAG在生成前检索外部知识，把非参数化知识作为当前回答的上下文，主要应对知识时效性、领域覆盖和证据追溯三个问题。[S1]

用图书馆作类比：模型像能解释问题的讲解员，知识库像可更新的书架，检索器负责找书页。找到一页主题相近的书，不代表这页支持你要说的每个结论；讲解员也可能遗漏条件。RAG不是事实保证器，必须分别检查资料、检索和生成。

贯穿案例的四份短文存于[统一案例数据](../lab_case.json)：

| 文档 | 合成内容摘要 | 课堂用途 |
| --- | --- | --- |
| lab-A | 先检索再依证据回答，检索不保证正确 | 区分检索与生成 |
| lab-B | 实验用500字符/100重叠，不是通用最优或token上限 | 保留参数单位和限制 |
| lab-C | 关键词与向量召回，RRF按排名融合，重排只排序已有候选 | 区分召回、融合、重排 |
| lab-D | 未提供报名截止日期，不得编造 | 无答案与拒答 |

这些短文仅供学习步骤演练，不能当作某所学校的招生规定。题目Q1问500/100的含义，Q2问RRF是否直接相加分数，Q3问没有提供的截止日期，Q4需要联合lab-A和lab-C解释完整链路。

## 2. 从经典 RAG 到模块化流水线

原始RAG论文比较了序列级和token级两种使用检索文档的方式：RAG-Sequence在整个输出序列上以同一批检索段落为条件；RAG-Token允许不同token综合不同段落。这里讨论的是原论文的概率建模，不能理解成普通应用每输出一个字就重新查询数据库。[E1]

现代工程通常把链路拆成可单独检查的模块：[S1，Retrieval pipeline]

~~~text
离线：来源登记 → 解析清洗 → 切片 → 文档编码 → 关系目录/向量与关键词索引
在线：问题与权限 → 查询处理 → 候选召回 → 融合/重排 → 证据包
      → 受证据约束的生成 → 引用/Claim检查 → 返回或降级
~~~

离线输入是文件及版本；在线输入是问题、学习范围和访问权限。离线产物可被多次在线查询复用，不能把“用户问了一个问题”理解为“重新编码整个资料库”。传统数据库查询也可以给生成器提供证据，不是所有RAG都必须先把资料迁入向量库。

**反例**：系统已经召回lab-B，却回答“所有资料都应使用500/100”。问题不在“没找到数字”，而在生成时删掉了“本实验”和“非通用最优”两个限制。

## 3. DPR 提供的稠密检索直觉

DPR使用双编码器分别编码问题和文本片段。文档向量可以离线预计算，查询只需编码自身后搜索候选，因而适合大规模第一阶段召回。[S2，PDF page 1]

双编码器的效率来自独立编码，但它在编码单条文档时看不到当前问题的全部交互。Cross-Encoder把问题与候选一起读入，适合对较小候选集精排；更精细不代表对每个问题都更准，也不代表它能找回根本没有召回的文档。

向量相似度分数只表达模型空间中的接近程度，不能直接解释为正确概率。lab-C可能与“RRF”最相关，但回答仍需检查它是否真的说明了融合算法。模型名、向量维度和高相似度都不能替代事实证据。

## 4. 离线索引与在线回答的工程边界

### 离线侧：可定位、可更新、可比较

文档记录至少区分稳定文档身份、内容版本、原始来源及物理文件位置；片段记录需要chunk_id、正文范围、内容哈希和切片策略。编码记录需要模型revision、维度、归一化、距离函数及输入长度处理策略。

文件移动和内容改写不是同一件事。只移动文件可能使路径引用失效，内容改写则可能使原片段证据失效。如何维持旧引用是系统设计决策，不能认为“文件名没变”或“向量数一样”就完成迁移。

### 在线侧：同一任务使用同一证据快照

候选除了正文，还应保留文档/片段ID、排名、分数含义、实际查询和知识范围。生成器与审核器必须使用同一组可核对证据，不能审核时悄悄查询更新后的另一份文本。

例如Q1的证据包只包含lab-B的当前版本；回答、Claim判断和引用都指向这条记录。审核器若打开另一版本的“默认800字符”示例，就不能据此评价原回答。

## 5. 什么时候需要检索

先判断任务依赖什么信息，而不是固定给所有输入都加检索：

| 输入 | 是否需要额外查知识库 | 原因 |
| --- | --- | --- |
| Q1：解释本实验500/100 | 需要相关实验资料 | 答案取决于实验约束 |
| Q3：查询没有给出的日期 | 可以检索确认范围，但不得补日期 | 检索不到证据不等于模型可以猜 |
| 把用户刚给出的短文改成列表 | 通常不需额外外部检索 | 所需文本已经完整给出 |
| 比较两个版本的规定 | 需要对应版本资料 | 不能只凭主题相似选一篇 |

“必须检索”是某类业务的规则，不是所有系统的普遍开关。对需要引用的领域事实，优先进入检索与证据检查；对知识范围外的问题，说明缺少资料或转交适当流程。Self-RAG的训练反思机制与应用层的规则路由也不是同一个实现，不能只加一个判断字段就声称复现论文。

## 6. 回答错误时的定位顺序

先保存原问题和本次输入版本，再按链路查证：

| 层级 | 要问的问题 | 案例中的反例 |
| --- | --- | --- |
| 语料 | 正确内容是否在本次允许的资料中 | Q3本来就没有日期 |
| 解析 | 条件、表头、否定词有没有丢 | lab-B丢了“不” |
| 切片 | 定义与限制是否被拆散 | 只取“500字符”半句 |
| 召回 | 正确片段是否进入候选集 | Q2候选中没有lab-C |
| 排序 | 正确片段是否被挤到截断之外 | lab-C排在证据预算之后 |
| 生成 | 输出是否超出证据 | 把实验参数说成通用标准 |
| 引用 | 引用是否支持具体Claim | 用lab-A支持500/100 |
| 依赖 | 索引或审核是否不可用 | 不能把超时当作“没有答案” |

有正确证据却错误改写，是忠实性问题；完全没召回，是检索问题；资料未给出，是可回答性边界。直接换更大的模型不能修复这些不同原因。

## 7. 项目验收清单

以下是教学验收建议，不是对当前仓库功能已完成的承诺：

- 回答能追溯到chunk_id、document_id和对应来源版本。
- 活动索引中的已废止内容不继续作为当前依据；历史审计记录是否保留另行规定。
- 查询、候选、引用与审核绑定同一次run和同一证据快照。
- 检索故障、空候选、无答案和审核不可用有不同记录。
- 无证据时系统明确拒答或降级，不把模型记忆伪装成知识库结论。
- “准确率提高”由固定实验支撑，不由一次演示截图支撑。

本仓库当前处于“资料文件已整理，旧SQL/Chroma尚待后续换模重建”的过渡阶段。文件检查通过不能证明旧索引已读到本次新教材；本轮内容优化不会调用模型或自动执行入库。

## 8. 完整案例：把课程资料变成可追溯问答

对Q1，先定位lab-B，再读取完整限制。一个合格的课堂回答是：“500/100按字符计数，仅为本实验基线，不等于模型token上限，也不代表所有资料的最佳值。”它至少包含三条可核验事实，应全部有lab-B支持。

对Q2，lab-C提供融合与重排关系。若只召回lab-A，正确做法是继续查找或说明证据不足，不是用“RAG先检索”的宽泛解释冒充RRF算法依据。第四模块将用构造候选展示这个失败。

对Q3，lab-D明确练习未给日期。合格输出不包含任何编造日期；“请补充有版本的报名通知”是行动建议，必须和“资料给出的事实”区分。第五模块会把这类回答拆成Claim；第六模块会同时测拒答与帮助性。

## 9. 推荐的跨模块数据契约

下面是课堂交付格式，不是项目HTTP DTO，也不是新增数据库字段要求：

~~~json
{
  "run_id": "lab-run-01",
  "case_version": "rag-lab-v2",
  "question_id": "Q1",
  "candidates": [{
    "document_id": "lab-B",
    "chunk_id": "lab-B-window-0",
    "document_version": "synthetic-v2",
    "rank": 1,
    "score": null,
    "score_kind": "not_measured",
    "evidence": "本实验切片基线是500字符、重叠100字符……"
  }],
  "outcome": "answerable"
}
~~~

没有执行检索就把score留空，不填一个看似真实的0.95。真正记录分数时还要说明距离/相似度/重排分、方向和产生它的模型版本。列表怎样存储是适配边界问题，不能让业务层丢失它的原始含义。

## 10. 是否启用 RAG 的决策树

按“任务依赖—知识覆盖—权限—证据完整性”四步作决定：

1. 是否需要近期、领域内、必须引用的事实？若是进入资料查询；只是改写已给文本则不必额外检索。
2. 当前知识库是否覆盖？Q3的日期没有资料，不能因向量搜索返回了四条就判定可回答。
3. 用户有权读取哪些资料？先限定可见集合，再召回，不依赖Prompt保密。
4. 最终证据能否共同支持输出？缺条件就补检索或说明不足，不能“凑够K条”即放行。

这棵树可以由规则、模型或混合方式实现；本章仅教决策依据，不把教学图当成仓库已部署的Agent工作流。

## 11. 三类典型失败的逐层定位

**流畅但错误**：lab-B被正确读取，输出却说500/100普遍最优。保留候选与最终Claim，对照限制词；不要把该样本归成“检索漏召回”。

**有引用但不支持**：回答解释RRF，却只附lab-A。引用文件存在只能证明定位成功，不能证明Claim被支持。要检查引用范围和实际语句。

**检索不可用与没有答案混淆**：向量库超时与Q3没有日期不同。前者应记录依赖错误、重试或降级，后者是资料范围内的正常无答案。将二者混算会把系统故障隐藏在拒答率中。

## 贯穿实验：交付一份不调用模型的诊断trace

**输入**：rag-lab-v2四篇短文，Q1–Q4，以及错误回答“所有资料都应采用500个token、100个token重叠”。

**步骤**：先给每题标answerable与相关资料ID；手动挑选支持段；把错误回答拆成“单位是token”和“所有资料最佳”两个Claim；查lab-B；给出修正回答和错误发生层级。

**期望产物**：四条题目记录、Q1的完整证据文本、两条错误Claim及更正理由。Q1关联lab-B，Q2关联lab-C，Q3无日期不得编造，Q4需lab-A与lab-C。

**失败排查**：如果Q3出现日期，查是否把模型记忆当输入；如果Q1只保留数字，查证据是否丢条件；如果无法定位版本，补case_version而非补造链接。整个实验无需Embedding或LLM，不能报告模型准确率。

### 参考答案与评分要点

- 第1题：不能保证；必须定位到具体层，不能全部归因于模型大小。3分。
- 第2题：离线有解析/切片/编码/索引，在线有查询/候选/证据/生成/审核；引用到同一版本。3分。
- 第3题：不应相同；一个是知识边界，一个是依赖故障。2分。
- 第4题：资料和题目是固定合成输入；score、时延和质量指标没有运行就不得伪造。2分。
- 本章10分仅供教学自测，不直接映射人物画像数据库状态或系统掌握度阈值；错题应回到对应小节学习。
