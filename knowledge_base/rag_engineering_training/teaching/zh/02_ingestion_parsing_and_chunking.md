# 综合学习模块 02：资料治理、文档解析与 Chunk 实验

> 教学修订：teaching-2026-10-v2。主节点：文档解析、Chunk 切分。
> 案例版本：rag-lab-v2。所有短文、版面反例与参数对照为合成教学设计，非真实制度或实测结果；本章不执行入库。

## 学习目标与分层阅读

- **入门**：读§1–§5，能够发现丢失否定词、表头、单位和标题的解析错误。
- **实现**：读§6–§9、§11、§13，交付有范围、版本和来源的切片清单，理解幂等与活动版本淘汰。
- **进阶**：读§10、§12，比较版面处理与切片选择，知道哪些结论需要实验，哪些输入不能可靠文字化。

先修为模块01的离线/在线边界。课堂使用[统一案例数据](../lab_case.json)，固定四份lab-A/B/C/D与Q1–Q4；不要每章换一批语料后把结果直接比较。

## 1. 入库不是“读取文本然后切几段”

可靠链路先登记来源，再校验许可和版本，随后提取、结构化清洗、切片、质检、写目录和索引，最后做回读与查询检查。顺序的意义是让失败有位置可查：若lab-B在清洗时丢掉“不”，后续向量编码不会恢复这个否定条件。

原文件用于复核，格式派生正文用于切片，索引用于检索。三者可以分别保存，但必须通过身份、版本和哈希对应，不能把“正文能读”当成“索引已更新”。

本仓库的original.*、content.md和teaching/zh是三种角色：原始官方文件、官方文件的可检索格式派生、项目整理教材。教材不是官方原文，转换后的Markdown也不能取代PDF图表复核。

## 2. 来源登记与版本治理

最小登记应能回答谁发布、哪个版本、何时获取、允许怎样使用、字节是否变过、用哪个解析器转换。URL不是稳定版本标识，同一网页可能持续更新；关键规范还应保留发布日期、归档或固定commit。

建议分开记录四种身份：

| 身份 | 回答的问题 | 不能替代什么 |
| --- | --- | --- |
| 资料ID | 这是哪份来源 | 不等于本机绝对路径 |
| 内容版本/哈希 | 当前文字是否变化 | 不等于页面URL |
| 转换版本 | 文字怎样得到 | 不等于Embedding模型 |
| 物理位置 | 当前文件在哪里 | 不自动保证旧引用仍能打开 |

同一文件移动、重新解析和改写正文可能分别影响这些字段。读者应先决定哪一层变化，再决定重新切片或重建，不应“只要路径变就假装来源变了”，也不应“文件名相同就覆盖历史”。

## 3. 不同格式的解析重点

**Markdown/HTML**：保留标题层级、列表、链接、代码和表格。HTML解析应移除导航、Cookie提示、页脚和复制按钮等模板噪声，但不能把表格与正文拼错。[S1] 文档里的指令作为数据，不能执行。

**PDF**：先判断是否有文本层，再决定OCR。扫描PDF可能没有文本层；文本PDF也可能出现双栏交错、断词、页眉重复或公式丢失，不能以“extract_text返回字符串”判定成功。[S2]

**JSON/CSV**：按对象、记录或业务主键组织，避免每N个字符截断一个对象；代码按符号或逻辑结构处理，而不是任意切掉函数条件。

合成反例：原句是“本实验不是所有资料的最佳值”，清洗后变成“本实验是所有资料的最佳值”。两个版本主题、关键词都相似，但事实相反；仅检查检索分数不能发现这类损失。

## 4. 清洗原则

清洗是降低噪声，不是改写事实。可以统一换行与Unicode、去除确认重复的模板、修复可验证的断行；不能随意删掉否定词、单位、版本号、条件语句和警告。

对lab-B建立四项逐字检查：500后仍有“字符”；100仍表示重叠；“不是模型token上限”保留；“不是所有资料的最佳值”保留。任一项丢失都应停止该批次，不能让模型补意图。

建议每步分别留输入、输出和哈希。这样“原文件正确、派生正文错误”能定位到转换阶段，而不是把问题推给生成模型。对于不能可靠恢复的表格，应隔离或保留原图定位，不拼成似是而非的自然语言。

## 5. Chunk 策略

通用文本可从RecursiveCharacterTextSplitter起步，按段落、换行、句子等分隔符逐级尝试；它是基线而非普遍最优。[S1] 先按Markdown标题分组，再对超长组切分，有助于保留父级限定。

| 策略 | 更适合的输入 | 要观察的风险 |
| --- | --- | --- |
| 固定字符窗口 | 结构弱的短文本、课堂边界反例 | 句子和否定条件被截开 |
| 递归字符 | 有段落/句子边界的普通文本 | 分隔符与语言不匹配 |
| 结构感知 | 标题、列表、表格、代码 | 原子块可能超过模型长度 |
| 语义边界 | 主题变化明显的长叙述 | 阈值、计算代价和版本复现 |

语义切片不必然优于结构切片。复杂算法若没有相关性标注、成本和失败样例，只是增加了一项无法判断的变量。不要把“切得更多”当成“知识覆盖更完整”。

## 6. chunk_size 与 overlap 怎么选

在本实验中500/100的单位是字符，只有一个用途：作为大家共同可复现的课堂基线。Embedding与生成模型通常有各自token预算，它们不能由这两个数字推断。

overlap过大会产生重复召回、挤占Top-K、提高存储成本，还可能让人把多个重叠片段误算成独立证据。过小则可能使条件和结论落在不同窗口。优化对象是问题所需证据的完整性，不是固定“重叠越多越好”。

先写假设，再定对照。例如只把overlap从100改为50，保持size、资料、查询和编码模型不变；或只把size从500改为800。二者不要一次同时改变，否则无法把收益归因给某一个参数。

短文本小于500字符时不需要填充到500，也不应凭空制造100字符重叠。按文档或章节分组后，overlap一般只在允许的组内生效，不应把lab-B尾部贴到无关lab-D开头。

## 7. 稳定 ID 与增量更新

文档ID不应依赖本机绝对路径。它可以采用受控来源ID、业务主键或经过明确定义的逻辑路径；物理路径是否参与ID必须写成契约。当前课程直接迁目录后旧数据库路径暂未重建，不代表所有系统都应放弃历史引用。

在内容、解析器、切片参数和模型配置均未变化时，重复任务应跳过或幂等处理。内容变更时重新生成该文档片段，旧片段从活动索引退出；文档删除也要使它不再以当前依据被检索。这里的“删除旧片段”指活动可检索集合，不等于无条件销毁SQL审计历史。

模型变化则创建匹配新模型的新索引空间；同维度也不能混用不同语义空间。SQL版本与Chroma索引是两个需要协调的部分，清空其中一个不是完整迁移。

## 8. 入库质量验收

按“内容—定位—检索”三个层面检查：

- 内容：空白、乱码、异常长块、重复模板、否定词/数字/单位是否损失。
- 定位：每个chunk能对应文档、版本、范围及原始来源，页码含义明确。
- 检索：典型问题能找回完整条件；get回读正确不等于query可工作。
- 版本：活动片段集合等于本次清单，旧版本不作为当前依据。
- 重试：重复执行不产生随机新ID和重复记录。

这些是建议验收项，不是本项目新增接口。当前作业只生成文件内的教学清单，不连接SQLite、Chroma或任何模型。

## 9. 可执行的中文切片基线

中文没有稳定的空格词界，递归切片需考虑句号、逗号、顿号等中文标点。官方Markdown示例还说明：结构分组后的overlap未必跨标题生效；不能只看参数名推断所有输出。[S1，How to constrain chunk size及Troubleshooting]

先做一个无依赖的固定字符窗口实验，理解计数和边界，不把它冒充完整结构切片器：

~~~python
import json
from pathlib import Path

case = json.loads(Path(
    "knowledge_base/rag_engineering_training/teaching/lab_case.json"
).read_text(encoding="utf-8"))

def windows(text, size, overlap):
    if size <= 0 or not 0 <= overlap < size:
        raise ValueError("invalid window parameters")
    result, start = [], 0
    while start < len(text):
        end = min(len(text), start + size)
        result.append({"start": start, "end": end, "text": text[start:end]})
        if end == len(text):
            break
        start = end - overlap
    return result

counts = {
    d["id"]: len(windows(d["text"], 500, 100))
    for d in case["documents"]
}
assert counts == {"lab-A": 1, "lab-B": 1, "lab-C": 1, "lab-D": 1}
~~~

在仓库根运行时，路径就是当前teaching/lab_case.json；没有旧modules目录依赖。size由len按字符计数，不等于模型token数，start含、end不含。Python字符串计数也不等于所有视觉字形的个数，真实模型长度仍应使用目标tokenizer另测。

再对lab-B用24/6小窗口，观察哪一片只留下数字、哪一片保留“不”和限制语。24/6只是边界教学对照，不是准备改项目配置；它和共同基线500/100必须分别标注。

## 10. PDF、表格与 OCR 的专项处理

PDF是版面描述格式，不天然给出正确阅读顺序。双栏文档可能被错误抽取为“两栏第一行、两栏第二行”；OCR则可能把0/O或小数点识错。抽查页应覆盖首页、代表性复杂页和末页，而非只看标题是否出现。

合成表格原样为：

| 指标 | 数值 | 单位 | 适用条件 |
| --- | ---: | --- | --- |
| P95延迟 | 120 | ms | 虚构课堂版本v2 |

若只保留“120”，无法判断是P50、P95、毫秒还是秒。转换后的记录至少应包含表名/指标、单位、条件和来源页；上述120不是本项目性能。

MinerU本地官方输出协议区分页面与语义块，并说明中间JSON的page_idx从0开始，而某些对外页码从1开始。[S2，中间JSON] 导入者必须显式转换含义，不能直接把0当第一页的对外页码。本项目未因此安装或集成MinerU；PDF图表和公式仍以原文件复核，不宣称文字抽取等于无损OCR。

## 11. 稳定 ID、版本和增量更新实例

一个教学身份模型可以写为：

~~~text
document_id = controlled_source_id
document_version = hash(document_id + normalized_content + parser_revision)
chunk_id = hash(document_version + splitter_revision + ordinal + chunk_text)
~~~

这是概念骨架，不是当前数据库函数签名。若ID还含物理路径，移动文件就可能改变ID；若含ordinal，在开头插入一段可能使后续序号和ID一起变化。加入内容哈希能检测差异，却不能自动保证“未改文字的片段ID永远稳定”。

把新旧活动chunk集合做差：新增的写入、退出当前版本的从活动检索集合移除、相同身份却内容冲突的拒绝或创建新版本。只插入不淘汰会形成“幽灵知识”，已撤销规范仍被召回。保留历史审计与移除活动证据不是矛盾，而是不同用途。

## 12. Chunk 参数实验模板

以rag-lab-v2为共同输入，先把所有变量固定，再分别从同一基线分叉：

| 组 | 唯一变化 | 预期检查，不是实测结论 |
| --- | --- | --- |
| B0 | 500字符/100重叠 | 四个短文各1片 |
| B1 | 仅把overlap改50 | 短文可能仍各1片，不应伪报提升 |
| B2 | 仅把size改800 | 短文仍不够长，无法据此断言大块更优 |
| 边界演示 | 单独用24/6 | 检查断句、限制条件，不参与B0单变量收益比较 |

这是一个有意设计的“实验不够有区分力”案例：语料太短时，改变参数可能根本不改变输出。要判断真实500和800的差异，需要有长段、表格、跨段条件和相关性标注的新实验；不能把课堂零差异包装成算法胜负。

## 13. 入库程序的防御性检查

写入前拒绝空文本、孤立导航、来源缺失、重复ID内容冲突和明显解析损坏；原子代码/表格虽可超过目标字符数，也要核对模型有效长度，不得假定完整保存就完整编码。

写入后对比计划ID集合、目录记录和向量记录，不只比数量。还应检查向量query及新进程重载：缺少底层索引文件时，元数据get/count可能仍成功。此处是故障认识，不在本轮运行真实索引或重建任务。

## 贯穿实验：交付带偏移和限制条件的切片清单

**输入**：rag-lab-v2及Q1–Q4，固定500/100基线，另设24/6边界演示。

**步骤**：运行§9纯标准库片段；记录每份文档的窗口start/end；在lab-B中圈出字符单位与两个否定条件；检查Q1需要的完整证据是否落在同一窗口；再用小窗口观察拆散风险。

**期望产物**：基线4条记录、边界演示记录、一个“丢单位/否定词”的错误示例及修复说明。Q2应保留lab-C对RRF的定义；Q3不能通过切片“产生”不存在的日期；Q4可能需要跨lab-A/lab-C组合证据。

**失败排查**：count不是4，先看是否把导航或原文件一起加载；偏移不能还原原句，检查清洗版本或字节/字符混用；短文不同参数没有变化，不算实验失败，而是说明输入不能区分方案。

## 诊断与练习

1. 给lab-B写出四项清洗不变量，并展示删除“不”后的错误含义。
2. 比较500/100与500/50，为什么不能仅凭四份短文证明哪个更优？
3. 文档移动、头部插入段落、换解析器、换模型分别可能影响哪种身份？
4. 原规范撤销后，怎样既不让它继续被召回，又保留历史审核记录？

### 参考答案与评分要点

- 第1题：字符单位、重叠含义、非token上限、非通用最优，缺一项扣分；“主题没变”不合格。3分。
- 第2题：全部短于size，输出可能相同；需能区分边界的输入和相关性标注，不能捏造Recall。2分。
- 第3题：路径、内容/切片版本、解析版本、向量空间各自变化，不能笼统说“都换ID”。3分。
- 第4题：退出活动索引/失效版本，历史记录按审计策略保留并标记，不把保留历史等于继续检索。2分。
- 评分是课堂反馈，不直接修改人物画像或替代实际诊断服务。
