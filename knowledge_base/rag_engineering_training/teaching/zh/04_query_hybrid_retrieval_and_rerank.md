# 综合学习模块 04：查询改写、混合召回与 Rerank

> 本课版本：teaching-2026-10-v2。贯穿案例 rag-lab-v2 是合成教学数据，不是业务规则、项目配置或模型实测；不下载模型、不调用模型。
> 能力节点：混合检索、Rerank。初学者先读 1、4、5、11；实现者完成 2、7、10、12；进阶者完成 6、8、9、13、14。

## 学习目标与分层阅读

完成本课后，你应能区分“找候选”和“给候选排序”，解释词项匹配与语义匹配的互补边界；对查询改写保留原问题、实体和否定关系；手算 Reciprocal Rank Fusion（RRF）；说明重排器看不到未召回内容；最后用相同输入规划质量、延迟和成本对比。这里的实验让你检验原理，不替你选择生产参数。

实现阅读重点是输入输出契约、候选 ID 与原始排名保留、故障降级；进阶阅读重点是候选池上限、长尾时延、分层评测和实验归因。若只想复习概念，可略读 6、8、13。

## 贯穿实验：rag-lab-v2（合成教学数据）

唯一案例文件是 [lab_case.json](../lab_case.json)。其中 lab-A 至 lab-D、Q1 至 Q4 均为虚构教学样本：Q1问切片单位和基线边界，Q2问RRF是否相加裸分，Q3是无答案，Q4问RAG与召回/融合/重排关系。Q2 的关键词排名是 A、B、C，向量排名是 C、A、D；k=60。RRF 的手算顺序预期为 A、C、B、D。文件附的重排分数 3.1、1.2、0.3、-0.5 也是人为构造的排序输入，不是模型输出，分数不是概率。不要据此写“混合检索提升了多少”或“模型更准”。

本课将固定这组候选做计算和排障。若你想测真实模型，必须另建获准的评测集、锁定模型与硬件、记录结果；这不属于本案例，也不是本课的通过条件。

## 1. 单路检索各自会漏什么

关键词检索依赖词面重合，适合精确术语、错误码、版本号和专名；它不会自动理解任意同义表达。稠密检索将文本映射到语义空间，能容忍部分表达差异，但“语义相近”不等于“结论相同”。在否定、数字、产品名和版本条件上，过度归一化可能把相反问题放在一起。

【初学】用 Q2 的“RRF 是否直接相加 BM25 和向量分数？”作例子：关键词通道可能抓到 BM25、RRF，向量通道可能命中关于融合的解释；两路返回的是候选，不是已验证的答案。【实现】保存每路的查询、过滤器、候选 ID 和名次；不要只留最终文本。【进阶】构造错误码、近义表达、否定句和无答案样本，分别统计每路漏召回。混合检索是否值得取决于这些错误类型，而非通道数。

## 2. 查询处理必须可回看

规范化可以整理空格、全半角等格式，但不能改写用户意图。实体保护要保留版本、路径、API 名、错误码、数字、否定词和比较关系。扩展词表要受控；多查询和问题分解应保留原问题，并为每个候选记录召回它的原始查询。这样排查时才能区分“原问召回不到”与“改写带来候选”。

固定输入例：“Python 3.11 下 Chroma collection 维度不一致，且不要重建索引，有没有办法？”可改写措辞，但变体必须保留 Python 3.11、Chroma、collection、“维度不一致”和“不要重建”的约束。若改写成“如何重建 Chroma 索引”，就是语义漂移。这个例子用于训练检查方法，不是 rag-lab-v2 的新增问题 ID。

## 3. HyDE 是检索探针，不是证据

HyDE 先生成假设文档，再对假设文档编码并搜索真实语料。假设文档的功能是提供一个更接近目标资料表达的检索向量；它可能含有编造细节，因此不能作为答案依据、证据片段或引用来源。最终证据必须来自检索到的真实资料，并接受正常的版本、权限和支持关系校验。

【初学】记住“假设文本用于找资料，不用于证明事实”。【实现】trace 中区分 original_query、hypothetical_text 和 retrieved_chunk_ids。【进阶】把 HyDE 与原查询召回做配对评测：同一问题、同一语料、同一候选 K，观察新召回到的相关片段和引入的噪声；失败时回退原查询。不得把假设文本本身当作额外 gold。

## 4. 稀疏、稠密与融合

BM25 一类稀疏方法按词项统计相关性；稠密双编码器按向量空间相似性取候选。两者原始分数通常不在同一量纲，不能不加依据直接相加。RRF 丢弃裸分数、使用各通道名次的倒数融合，因此可以在排序层面组合多个通道。它不会让单路都没有召回的资料凭空出现，也不保证每个任务的指标都上升。

教学公式如下，rank 从 1 开始：

~~~text
RRF(d) = Σ_i 1 / (k + rank_i(d))
~~~

【实现】先用稳定候选 ID 合并同一资料，记录每路排名和最终 RRF 分；缺席通道不贡献项。k 是融合参数，不是候选 Top-K，也不是通用最优值。rag-lab-v2 只固定 k=60 供手算，不把它升级为项目默认设置。

## 5. Retrieve & Re-Rank 的边界

Cross-Encoder 同时读取查询与候选文本，通常通过 token 间联合注意力做更细粒度的相关性判断；这不保证每个任务都更好。每个查询—文档对都要推理，不能像双编码器文档向量一样完全预计算。常见教学设计先召回几十到上百条，再重排保留少量证据；这些数量仅是起步范围，不是当前系统设置。

双编码器或关键词检索先从较大语料快速召回候选；Cross-Encoder 对查询和每条已召回候选联合打分，再调整顺序。它能重排当前候选集，不能找回候选集之外的片段。若正确资料没有进入候选，换更强重排器不会修复 Recall。还要保留召回名次、通道、原始分数和来源，不要用重排分覆盖它们。

【初学】候选是“参赛名单”，重排是“名单内排序”。【实现】比较重排前后的首个相关结果、NDCG、耗时和输入截断；把候选 K、最终 K 分开记录。【进阶】分别检查跨语言和领域适配，不要从英文公开例子推出中文项目的效果。

## 6. 候选数量与时延预算

召回 K 太小，相关资料可能进不了重排器；K 太大，重复和无关项会消耗重排时延及后续上下文预算。候选规模、每个候选长度、批量大小、并发数和超时必须一起测。总时延应拆为查询处理、各通道召回、融合、重排、上下文构造和生成；不能给每一层都分配完整端到端 SLA。

rag-lab-v2 没有延迟或成本数据。实验记录表中的时延、成本应写“待测”，不能依据本地手算填数。若没有测量条件，至少保留预测瓶颈和未验证项，不把估算写成 P95。

## 7. 去重与多样性

同一文档相邻重叠片段可能几乎重复；精确去重可先按 chunk ID，文本相似去重还需记录规则和阈值。不同来源的相同结论不一定是重复：若来源独立且可增强证据可信度，应保留来源映射。合并片段时保留原始片段 ID、原排名与合并理由，否则最终引用可能打不开或看不出证据来自哪里。

练习时对 Q2 的结果按 ID 融合，不能把 lab-A 在两路出现误算为两份独立证据。若把相邻片段合并，输出至少包括 merged_id、member_ids、source_ids 和各路名次。

## 8. 常见故障：症状要对应验证

- 精确编号不见：先比较原查询与改写，再检查关键词通道和过滤器。
- 向量候选语义相近但条件错：核对版本、否定、适用范围，并看原文，不靠分数证明正确。
- RRF 顺序异常：检查 rank 是否从 1 起、同一候选是否按 ID 合并、k 是否一致。
- 重排后正确片段更靠后：检查候选是否完整、模型语言/领域、输入截断和排序方向。
- 重排后 Recall 变低：若 Recall 指“重排输出前 K 中找回的相关资料数”，检查 K 是否缩小；固定候选集的重排本身不能补回缺席候选。
- 延迟长尾：分阶段测量并检查最大候选长度、批量和并发；不要只平均总耗时。

## 9. 对照评测的最小协议

同一问题集、语料版本、相关性标注和权限过滤下，比较关键词、稠密、混合、混合加重排。保存逐题结果，至少统计 Recall@K、MRR、NDCG、候选重复率、空召回率和 P50/P95；如果没有真实测量，留空并写明原因。检索指标只描述候选，不等价于最终答案正确、引用正确或 groundedness。

先固定主要指标和失败类别，再查看结果；不要只在观察结果后挑一个最有利指标。对比时按问题类型分层，精确编号题、近义表达题和无答案题的变化可能方向不同。

## 10. 查询改写的输入输出契约

改写记录至少有：original_query、protected_terms、rewrites、strategy、rewrite_version，以及每个候选对应的 source_query_id。排序链还要保留 chunk_id、retrieval_channel、retrieval_rank、原始分数及其度量方向。改写输出是检索输入，不是给用户的回答；合并候选后仍能反查到原始问题和每个通道。

rag-lab-v2 中 Q2 的保护词至少包括 RRF、BM25、向量、是否/“直接相加”；不得把提问改成“RRF 如何提高召回”。Q3 是无答案题：不能为了让检索有结果而自动把虚构的报名日期补进查询上下文。

## 11. RRF 手算：固定输入与期望产物

按 lab_case.json 中 Q2 的两路排名计算，k=60，rank 从 1 起：

| 候选 | 关键词排名 | 向量排名 | 计算 | RRF 分（约） |
| --- | ---: | ---: | --- | ---: |
| lab-A | 1 | 2 | 1/61 + 1/62 | 0.03252 |
| lab-C | 3 | 1 | 1/63 + 1/61 | 0.03227 |
| lab-B | 2 | 无 | 1/62 | 0.01613 |
| lab-D | 无 | 3 | 1/63 | 0.01587 |

因此顺序为 lab-A、lab-C、lab-B、lab-D。表中数值是对合成名次手算，非系统或模型运行结果。可用纯标准库复算：

~~~python
from collections import defaultdict

rankings = {
    "keyword": ["lab-A", "lab-B", "lab-C"],
    "dense": ["lab-C", "lab-A", "lab-D"],
}
scores = defaultdict(float)
for result_ids in rankings.values():
    for rank, doc_id in enumerate(result_ids, start=1):
        scores[doc_id] += 1 / (60 + rank)

order = sorted(scores, key=lambda doc_id: (-scores[doc_id], doc_id))
print(order)
~~~

期望输出是 ['lab-A', 'lab-C', 'lab-B', 'lab-D']。若把结果改成只包含关键词前三项和向量前三项的并集，D 仍会出现；若某文档不在任何一条输入列表中，融合代码不会生成它。调试时逐项打印分数，避免只对最终顺序“凭感觉”检查。

## 12. 重排接口：伪代码而非可运行模型

本节只定义应保存什么，不加载模型，也不指定中文模型：

~~~text
input: query, retrieved_candidates
for each candidate:
    preserve chunk_id, source, channel_ranks, retrieval_scores
    compute rerank_score(query, candidate.text)  # model adapter; not run here
sort candidates by the adapter's documented score direction
return top_n plus the original retrieval trace
~~~

rag-lab-v2 的构造分数若用于手算，顺序为 lab-C、lab-A、lab-B、lab-D；这是 fixture 中的 synthetic_rerank_scores，不代表 Cross-Encoder 接口一定输出这些值，更不是模型准确度。接入某个后端前，需要核实它的 API、模型适配语言、分数方向、最大输入和许可证。重排层不拥有来源事实，也不能更改证据正文。

## 13. 超时与降级

改写依赖不可用时可按产品策略回退原查询；单一召回通道失败时要明确记录剩余通道；重排超时可回退融合名次，但结果需标为降级。所有检索通道不可用时，应返回检索失败/证据不足路径，不能无证据转为自由生成。每种降级都要定义错误状态、可观测字段和是否允许继续回答，本课不替项目规定 API 错误码。

【实现检查】用故障注入或可控 stub 验证：每种失败能被区分、trace 能显示缺失阶段、原始查询仍保留、无证据分支不生成伪引用。rag-lab-v2 不含服务端故障数据，因此只可设计检查，不可报告已验证。

## 14. 症状—验证—修复决策

候选 K 太小时，重排器看不到遗漏的正确文档；若还缩小输出 K，输出前 K 的 Recall 甚至可能降低。固定候选全集时，仅改变排序不会改变全集召回率，比较时必须写清截断范围。

| 症状 | 先查什么 | 下一步 |
| --- | --- | --- |
| 编号搜不到 | 原问、保护词、关键词通道 | 修正改写或通道，不先加生成温度 |
| 重复候选多 | chunk_id、相邻片段关系、每路排名 | 合并并保留全部来源 |
| RRF 结果难解释 | 各路 rank、k、缺席通道 | 复算单条候选 |
| 重排后效果差 | 初始候选 Recall、语言与截断 | 先修候选/输入，再做受控模型评估 |
| 延迟升高 | 阶段 P50/P95、候选数和长度 | 找长尾阶段后设预算 |
| 无答案题有候选 | Q3 相关性标签与拒答规则 | 允许空召回；不把邻近文本当答案 |

## 诊断与练习

1. 【初学】回答 rag-lab-v2 的 Q2：分别写出关键词、向量和融合排序；解释为什么不能把两个裸分数相加。
2. 【实现】只用 Python 标准库复算 §11 的 RRF 表，输出排序和每个候选的分数；再说明当一个目标片段不在任何一路候选时会发生什么。
3. 【实现】把 §12 伪代码改成输出字段清单，保证重排后仍能回溯 chunk、来源和原始名次。
4. 【进阶】为精确编号、同义表达、否定条件、Q3 无答案设计对照表；列出同一评测集下比较的指标与至少两个失败分析字段。不要填虚构跑分。
5. 验收：能说出 RRF 的名次输入、Cross-Encoder 的候选边界、HyDE 的证据边界；能用固定输入复现 A、C、B、D；所有尚未运行的质量/时延结果明确标为待测。

### 参考答案与评分要点

- 第 1 题：关键词 A、B、C；向量 C、A、D；RRF 为 A、C、B、D。它融合名次而非不同量纲的裸分。顺序和解释均正确得 2 分。
- 第 2 题：代码对每路使用从 1 开始的 rank，累计 1/(60+rank)，同 ID 合并；期望顺序 A、C、B、D。两路都未召回的 ID 不会出现在输出。算式/实现 3 分，候选不可恢复边界 1 分。
- 第 3 题：至少保留 chunk_id、正文、source、channel_ranks、retrieval_scores、rerank_score 和 score_direction；重排不覆盖原排名。字段完整 2 分。
- 第 4 题：问题集合和知识库快照固定，分别跑对照通道，报告 Recall、MRR/NDCG、重复率、空召回和延迟；数字/版本/否定词应对照原问题。指出至少两类风险得 2 分。
- 总分 10 分；把合成名次或伪代码写成真实模型实测，或把 HyDE 假设文档列为证据，不通过本课验收。
