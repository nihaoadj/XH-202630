# 报告读取基准（2026-10-23）

T22第四优化方向的本地合成结果。使用锁定Python3.11环境、SQLAlchemy 2.0.35、SQLite 3.53.2；不调用模型或读取业务数据库。两个结果集均已实际运行并以退出码0完成。

## 复现与口径

```powershell
python backend/scripts/report_benchmark.py --output output/test-runs/report-benchmark --sizes 100 1000 10000 --repeats 3
```

固定30个资源、6个Run、100/1000/10000条正式历史，包含发布修订和同Run多个资源类型及精确Review/Claim绑定。图谱大小不是变量。初始化完成后测暖GET/304、5条可信度页、单订阅/三订阅真实poll函数，各3次；时钟和种子相同，脚本SHA与三个input_hash逐一一致。SQL是执行语句数，ORM是装载对象数，不是物理扫描行；P95在3样本中等于最大值，不是稳定的线上延迟分布。内存为tracemalloc范围内的Python峰值。

GET测量包含HTTP TestClient，SSE poll不包含实际网络长连接、心跳等待或跨Web进程调度。冷构建不在暖路径时间表中，另由10001完整历史/批量读取专项检查。SQL CTE可扫描候选元数据，但只装载limit+1个资源正文。

## 查询和构建次数

下表单次 `SQL / ORM对象 / 完整build`；普通GET、304和单订阅poll的计数相同。

| 正式历史 | 改前GET/304/单poll | 改后GET/304/单poll | 改前三订阅poll | 改后三订阅poll |
|---|---|---|---|---|
| 100 | 732 / 1516 / 1 | 4 / 2 / 0 | 2196 / 4548 / 3 | 12 / 6 / 0 |
| 1000 | 2532 / 5116 / 1 | 4 / 2 / 0 | 7596 / 15348 / 3 | 12 / 6 / 0 |
| 10000 | 20532 / 41116 / 1 | 4 / 2 / 0 | 61596 / 123348 / 3 | 12 / 6 / 0 |

5条资源页的计数从 `148 / 356 / 0` 变为 `8 / 33 / 0`，三个规模相同。33个对象包含页及lookahead资源、对应审核/Run证据和权限画像，不能解读为33个正文资源。

## 10000条历史的耗时和内存

峰值为该case三次样本中的最大值，MiB按1024²换算。

| 场景 | 改前P95(s) | 改后P95(s) | 改前峰值(MiB) | 改后峰值(MiB) |
|---|---:|---:|---:|---:|
| get | 19.676639 | 0.013219 | 46.962 | 0.584 |
| conditional_get | 20.831959 | 0.009226 | 47.065 | 0.089 |
| resource_page | 0.151258 | 0.092170 | 0.325 | 0.227 |
| sse_poll | 19.127464 | 0.003137 | 46.944 | 0.062 |
| sse_multi_poll | 79.500987 | 0.018107 | 138.830 | 0.179 |

改后10000规模分页有一个约92ms的慢样本，原样计入P95；没有剔除或补跑以改善数字。收益主要来自暖快照复用和不再装载全部资源正文，不能据此推导真实用户容量或冷构建上限。全局epoch在其他学习者写入时也会保守失效；缓存不跨进程共享。
