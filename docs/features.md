# 功能文档

> 项目编号：XH-202630
> 项目名称：领域知识个性化生成与多智能体协同决策系统
> 文档版本：2.4
> 文档更新时间：2026-10-09
> 文档定位：说明当前系统已经落地的能力边界、核心流程和页面职责。

## 1. 当前产品定位

系统面向多领域技能学习，当前提供账号与资料、五步方向引导、能力定阶、异步文本资源生产、互动课件、证据约束 Tutor、正式测评反馈、学习旅程和动态学情报告。用户稳定资料、方向问卷、客观掌握度和课程进度分别维护；后续资源依据持久化事实和学习者确认的节点生成。

## 2. 当前闭环

```text
注册 / 登录，按需维护用户资料
-> 选择学习方向
-> 填写通用问卷
-> 生成初始画像
-> 进入能力诊断
-> 发起资源生成任务
-> 查看资源列表或下载资源
-> 提交学习反馈
-> 查看判分与下一步候选，确认后创建后续任务
-> 查看学习历史时间线与学习报告
```

## 3. 已完成的核心重构

### 3.1 用户资料与问卷拆分

当前已经完成职责拆分：

- 用户资料负责维护稳定信息：
  `display_name`、`identity`、`education`、`major`、`job_role`、`experience_years`
- 通用问卷只负责维护当前学习方向下的动态信息：
  `learning_goals`、`learning_modes`、`difficulty_preference`、`weekly_time_budget`

已经移出问卷的字段：

- `identity`
- `education`
- `major`
- `desired_resource_types`

### 3.2 用户 ID 自动生成

当前用户资料创建流程中：

- `user_id` 由后端自动生成
- 前端不应让用户手动填写或编辑 `user_id`

### 3.3 异步资源生成

资源生成已经切换为异步任务模式：

- 创建任务：`POST /api/generate/jobs`
- 查询任务列表：`GET /api/generate/jobs?learner_id={learner_id}`
- 查询状态：`GET /api/generate/jobs/{run_id}`
- 查看结果：`GET /api/resources/{learner_id}?run_id={run_id}`
- 下载文件：`GET /api/resources/file/{resource_id}`
- 读取单资源详情：`GET /api/resources/items/{resource_id}`

同步生成接口 `POST /api/generate/` 已移除。

当前前端已补充任务维度展示：

- 资源生成页默认展示当前 `running/queued` 任务
- 支持切换查看历史成功任务
- 任务内再选择具体资源阅读或下载
- 运行中的任务展示资源级生成/审核进度；已批准资源可在整批完成前阅读

资源类型不再共用一个生成 Prompt。首期固定支持：

| 类型 | 专用 Agent | 默认调用输出预算（token） | 表示 |
|---|---|---:|---|
| 讲义 | `TextResourceAgent` | 65536 | Markdown 文本 |
| 实操指南 | `PracticeGuideAgent` | 65536 | V3 严格 JSON：固定准备、实操、验证、复盘四阶段；每个步骤仅含说明、操作、代码块、验证四个内容字段。服务端确定性拼接 Markdown，JSON 直接驱动互动 HTML 阶段页与步骤页 |
| 分阶测试题 | `AssessmentAgent` | 65536 / 节点调用 | 每节点 2 道基础单选、2 道进阶多选、2 道挑战简答；单节点 100 分，分值为 15/15/20/20/15/15，多选支持部分得分与错选扣分 |
| 复习清单 | `ReviewChecklistAgent` | 16384 / 节点调用 | 按能力节点生成的主动回忆 Markdown：闭卷回忆、概念辨析和可选正反例辨认，最低 `1+1+0`；答案集中于文末 |
| 案例分析 | `CaseStudyAgent` | 16384 | Markdown 案例分析 |
| 个性化纠错训练包 | `CorrectionTrainingPackageAgent` | 32768 | 仅正式反馈后的薄弱点强化 Markdown；提示词提供推荐章节，但审核不因标题、章节顺序或小节排版偏差直接失败，仍检查内容安全、证据范围、知识点覆盖和难度 |

这里记录 `config.py`、ResourceSpec 和 Agent 调用合成后的默认预算，不以类上的旧 `default_max_output_tokens` 单独推断。讲义、实操与通用资源预算可由配置覆盖；案例和纠错包使用显式调用上限，节点型资源可能有多个有界调用。超时、重试和部署模板说明见 [部署说明](deployment.md)。

`定制讲义` 是唯一兼容别名并会规范化为 `讲义`。未知类型在任务创建和模型调用前拒绝；普通前端只展示五种通用类型，个性化纠错训练包只在反馈结果中显示。

### 3.4 学习历史与学习旅程

系统保留兼容的历史时间线入口：

- `GET /api/learning-history/{learner_id}/timeline`

同时提供面向学习者的完整学习旅程：

- `GET /api/learning-history/{learner_id}/journey`

历史页默认展示当前学习节点、最近测评和下一步建议，并按资源批次组织“生成 → 资源 → 测评 → 反馈 → 路径变化”的可展开轮次。同一批次内的普通追加与定向重试共用同一反馈与路径变化链路；反馈后的个性化纠错训练包及其新分阶测试题即使复用原批次号，也保持独立测评链路；页面复用持久化的 Attempt、反馈决策、掌握度、路径、资源及 Run 审计摘要；旧记录缺少可靠关联键时保持为独立历史事件，不推测因果关系。

历史页的画像切换、首屏加载和分页均按所选画像归属；切换时清理旧旅程，晚到响应不会覆盖新选择。时间范围同时筛选轮次和未关联事件。删除画像后会自动选择相邻的剩余画像并加载其旅程。

### 3.5 模块级节点优先检索

带 `target_skill_nodes` 的资源请求默认先在能力节点映射出的模块 Chunk 范围内执行
Chroma 向量召回、BM25、RRF 和精排；多个目标节点取 Chunk 并集。范围内没有映射、
无命中或未达到既有 Evidence 门槛时，自动复用原全库混合检索。底层检索异常不回退，
以保留既有错误和降级语义。

该能力不改变生成、审核、发布、资源来源 API 或前端接口。范围缩小用于减少无关上下文，
但不替代现有 Evidence Gate、Chunk 版本/哈希校验和 Claim 审核；最终证据仍可来自多份文档。

## 6. 当前前端交互约定

### 学习工作台

- `/dashboard` 使用深海蓝学习主面板与浅色连续分区：方向标题、下一步建议和操作分别组织为三个纵向区域，扩大文字间距并平衡图文比例；摘要使用一体化仪表条、统一水平线的线性图标、细色线与不同字阶，不使用无数据含义的趋势折线。四个工具入口组成连续网格，与右侧纵向学习闭环共用标题高度和内容边界。蓝青主按钮、描边次按钮与顶栏文字入口区分操作层级。
- 工作台提供“切换画像”弹窗，显示已有画像的名称、方向、阶段与目标，标记当前画像；取消/关闭保持原选择，空目录可新建方向，目录加载失败可重试。完整读取现有画像分页目录，选择后复用既有画像恢复与持久化字段，刷新方向、阶段、资源数、时间和推荐；加载期间暂禁推荐按钮，迟到的旧画像响应与卸载后的响应不会覆盖当前摘要。列表较长时仅弹窗内滚动，可通过键盘选择。
- 推荐逻辑保持既有规则：无画像进入新建方向，有画像但无资源进入生成，有资源进入阅读；资源计数、画像阶段与最近时间继续来自现有接口。协作 SVG 为静态机制示意，不表示实时任务状态。
- 所有学习页共用深海蓝侧栏、青色激活标记、品牌和底部操作，五个导航在桌面导航区域等高分布；保留折叠状态及原有历史/报告/资料入口。收起/展开直接落地布局状态，通过平移和裁切补间衔接，快速反向、路由切换、窗口调整和减少动态效果偏好变化会取消旧动画；图标与文字不缩放，折叠后的学习上下文不会获得键盘焦点。公开首页、认证页和资源专注模式保留各自外壳，其他学习页正文保持原有滚动行为。
- 同一学习外壳内的页面切换优先使用浏览器原生快照过渡，不支持时用透明度回退；专注模式和公开页外壳切换使用实时透明度动画，固定控件在进场期间仍可点击。共用账号弹窗的登录/注册切换只淡入表单；问卷标题按前进/返回方向轻微位移，资源、反馈、历史和报告的局部更新只淡入。动画不增加业务组件挂载，不改变页面滚动或固定控件位置；输入、报告事件流和同页 URL 更新不重复触发页面动画，减少动态效果偏好会禁用或取消动画。浏览器证据见 [页面动效专项](testing/motion-ui.md)。
- 工作台一屏正文样式仅应用于 `/dashboard`，顶栏主题与 `/learning/new`、`/generate` 共用。桌面视口宽 ≥1100px 且高 ≥640px 时按高度分配网格，在实测正文、摘要、工具、闭环和页脚完整容纳后固定为一屏，滚轮、翻页键和程序滚动保持原位；窗口变化与摘要更新后重新检查。窄屏、极低窗口或超长内容无法容纳时保留自然阅读，平板和手机使用紧凑横向导航。观察器与动画帧在卸载时清理，键盘焦点可见，减少动态效果偏好下取消非必需过渡。
- 浏览器专项使用隔离 fixture 覆盖响应式、一屏完整显示及实际禁止滚动、窗口变化和长内容降级、其他学习页实际滚动、推荐状态、原入口路由、折叠持久化、焦点、文字对比度与无业务写请求，命令见 README“测试运行”。

### 新建学习方向

- `/learning/new` 与工作台共用清洁顶栏、浅灰画布及深海蓝侧栏；页内五步导航使用连续路径，明确当前、完成与后续状态。领域/方向选择采用编号、线性图标、资料信息和青色选中标记，概览使用连续分隔，主按钮与返回操作层级清晰。
- 问卷采用连续编号、可见标签、题型提示和独立说明；诊断选项采用整行可点击的单选/多选区域，长内容允许换行。诊断结果用深蓝画像摘要、优势/薄弱点与首个推荐节点呈现；五类资源有用途说明，Claim 开关与补充要求单独确认。
- 保留四类问卷取值、条件题、诊断复测和无题跳过、初始节点推荐、五类资源默认选择与 Claim 多类型拆分。领域/方向在桌面宽≥1100px且高≥640px时按可用高度分配区域，实际内容完整容纳后固定一屏、禁止滚动；窗口、侧栏、目录变化会重新测量，不裁切选项或按钮。额外大目录、长内容、窄屏或极低窗口保留自然阅读；问卷、诊断与资源确认固定顶部介绍、步骤、卡片标题和页脚，只有右侧卡片正文内部滚动；滚动边缘不带动外层，题目和最后操作可达，题区可获得键盘焦点并使用翻页键。高度不足或固定区溢出时回退正常阅读。窄屏采用紧凑五步指示。步骤切换回到新标题且保留答案，支持键盘焦点及减少动态效果，观察器/动画帧在卸载时清理。
- 专项使用隔离 fixture 检查五步渲染、八个视口、表单和原生成 payload，不调用实际后端或模型；命令和证据路径见 README“测试运行”。

### 6.0 初始页面与账号访问

- `/` 展示六屏入口：学习概览、平台能力、协作星图、证据档案、成长航线、反馈进阶依次排列。桌面各屏占满顶部导航以下的视口；纵向滚轮每手势切换一屏，支持反向中断、方向键、PageUp/PageDown、Home/End、六个竖线页码和能力链接，当前竖线同步更新；页码不展示数字或外层包裹气泡，保留章节标签、提示与点击/键盘操作。
- 桌面视口（宽≥821px且高≥680px）始终显示六个竖线导航；正常高度章节按约760ms统一时钟平滑翻页，同向连续滚轮输入不打断当前翻页。个别章节超高时先自然阅读，到内容边界后的下一次手势再换页，不影响其余章节导航；所有章节完整装入视口时启用严格整屏吸附。窄屏、低高度保留自然滚动；窗口变化、弹窗打开或减少动态效果偏好变化会清理翻页动画，减少动态效果直接定位，系统缩放手势和原生触摸保留。
- 顶栏保留品牌首页入口与账号登录，不重复展示“平台能力”链接；该章节仍由首页“了解平台能力”和竖线导航进入。
- 首页容器、正文、按钮、流程节点与能力卡片按桌面宽度调整尺寸，提高全屏后的可读性和空间利用率；紧凑窗口保留完整内容，不通过裁切强制分页。
- 首页登录入口、`/login?auth=1`、`/register?auth=1` 和首页 `?login=1`/`?auth=1` 复用账号弹窗。桌面采用品牌介绍与表单双栏，窄屏优先展示表单。 账号区域采用瓷白/冰蓝/淡紫明亮配色，左侧原创SVG开放轨道与独立品牌光晕、三个精简能力标签，右侧独立白色表单；图形自动缓慢悬浮与外圈光点循环，关闭弹窗时停止、减少动态效果时静态，不增加暂停控件。弹窗高度受视口限制；补充资料在右侧表单区域内滚动，左侧和关闭按钮固定。

#### 四项特色展示

- 首页第二屏的四张卡片直接滚动到后续特色章节，地址 hash 支持直达、刷新与历史导航。原 `/features/multi-agent`、`/features/evidence`、`/features/learning-path`、`/features/feedback-loop` 重定向到对应首页 hash；展示共用同一场景实现。
- 协作星图采用紫色 Agent 网络，明确显示诊断、规划、资源生成、常规审核和可选 Claim 审核的身份、职责与输入/输出；中心表示共享工作流状态。检索和证据门禁为工作流节点，不冒充 LLM Agent。五个角色按72°等角、等半径对称分布，SVG与卡片共享坐标，径向连线使用统一规则；有限演示明确包含可选 Claim 分支，每步约1.8秒、五步约9秒；未选中保持暗底，当前角色以亮紫背景、边框、图标及对应亮连线突出，状态平滑过渡，完成后仍仅当前角色/连线选中。可暂停、继续与重播，不表示实际模型运行。
- 证据档案使用浅色溯源画布：紧凑的 Claim/Evidence 沿轨迹指向端正的右侧来源面板，第四步独立判定位于来源左下侧，以较长连线接续；两处关联说明移到线旁，不遮挡光点。四步每轮约12秒自动循环，光点/描线/阶段共享计时；末段走完1500ms才亮起判定，结果停留2700ms后重置。提供暂停/继续，规则组键盘阅读暂歇、显式暂停优先，离屏/遮罩/隐藏保留进度，减少动态效果呈现静态最终结果。三个规则保留 `supported`、`not_in_evidence`、`contradicted` 的 Evidence 绑定约束；无依据时来源保持未绑定，光点从证据直接进入判定。来源字段为知识库/文档版本/Chunk、章节/行号与摘录哈希，文档只有字段结构与抽象片段示意；不展示实际文档、论文、伪造来源 ID、外部原文链接或真实审计结果，注明 Claim 审核需开启。
- 成长航线直接使用默认 `rag_engineering_training` 的三阶、13 个真实节点与 15 条先修边，按三个竖向阶层列排布。各列顶部切换“诊断定阶为第 1/2/3 阶”的条件，突出当前学习阶与低阶的初始豁免；节点按先修顺序排齐，跨阶边沿列间通道，点击节点突出其直接前置并显示详情。豁免标为未以测评验证，不是正式掌握，本阶节点完成后才解锁下一阶；不按职业背景推断个人路线。窄屏各列顺序堆叠，公开展示数据由浏览器专项与仓库 metadata 比对。
- 反馈进阶以“反馈，让学习路线转折”为主标题，用编号进程串起测评依据、主体路线转折和选择确认；反馈章节使用暖象牙底色、深琥珀强调色；三个步骤均由灰米色的未选中底色切换为亮象牙色的选中底色，第二步进入路线重排后再平滑亮起标题、边框与节点。学习节点 A 表示本轮节点，B 按分支标明未掌握的前置候选或满足可学条件的后继；巩固分支展示纠错训练包和回到 A 的新测评。正式反馈的 60%/80% 策略分为三种路线建议：总分或知识点低于 60% 时回溯未掌握前置；60%–低于 80% 且无阻断时默认纠错包巩固，配套新的分阶测评；达到 80% 且无阻断时按先修/阶级条件推进。高分不代表已经解锁下一阶，后续生成需学习者选择确认，确认低阶节点后才改变当前阶。A、B 为抽象机制说明，不绑定特定知识点、个人成绩或已执行任务。
- 进入活动反馈章节后无需点击，按测评 3 秒、路线 5 秒、确认 4 秒的节奏自动循环当前规则；不自动切换所选规则。路线、移动标识和进度条共享同一阶段时钟，标识沿连续路线在 4.3 秒内走完，终点停留 0.7 秒后再进入确认；固定圆点位于实际弯道中心，FEEDBACK 提示紧贴其左侧；三分支使用相同转弯位置和节点排布，按 B→A 回补或 A→B 进阶的实际文案解释变化。常驻暂停/继续按钮，鼠标切换规则或步骤后继续自动播放；键盘焦点进入时暂歇、移开后继续，主动暂停保持优先。暂停/离屏/账号遮罩/文档隐藏时停止阶段计时与动画帧，恢复时从保留进度继续，不重启标识。动态切换 `prefers-reduced-motion` 会停止循环并显示完整静态机制，卸载清理计时器、动画帧及监听。循环状态不使用 live-region，避免重复播报。
- 每页保留主标题、简短说明和当前选择的重点；英文主题标签作为视觉辅助。四页均显示“项目机制示意”标记，全部本地运行，不新增业务 API。
- 平台能力第二屏使用浅玫瑰灰、瓷白和深玫瑰红主题；英文主题标题与四个能力动词配合中文主标题，四项入口以连续面板呈现协作网络、来源档案、分支路径和反馈转折的原创 SVG 示意。文案每项一句，保留四个章节锚点和账号入口；入场有限描线、悬停轻微抬升，减少动态效果时静态显示。桌面保持完整一屏，平板两列、手机一列。
- 六屏均采用配套亮色主题：学习概览浅冰蓝、平台能力浅玫瑰灰、协作星图浅紫、证据档案浅绿、成长航线浅靛蓝、反馈进阶暖象牙；文字与图示使用相应深色，保留节点/选中态层次。顶栏背景、品牌文字、导航按钮及竖线页码随当前章节配色，顶栏与正文使用同一底色。桌面采用大幅场景与可读字号；窄屏和平板纵向排列并允许自然滚动。进入章节触发有限入场与连接过渡，减少动态效果时直接展示可读状态；离屏或打开账号弹窗停止角色/反馈演示计时器，返回后可继续。验收命令与证据路径见 README“测试运行”。

### 6.3 资源生成

- 无任务时使用资源工作区准备画面：上部结合目标说明与专属“画像输入—多智能体协作—发布输出”的静态线路示意，下部以连续三分区介绍确定起点、组织资源、进入学习，保留新建方向入口。与学习页保持雾白/浅青色、细线和操作风格，示意图独立设计；页尾贴近主体，不增加独立分隔线。有任务但尚无发布产物时，在预览区域显示对应的等待、失败或同步说明与后续步骤，仍可查看真实轨迹及使用当前任务操作。初始展示不使用大图居中占位，也不虚构生成进度。
- `/generate` 保留原有顶部整行分布：画像/批次横排，方向/编号/状态/数量/创建/完成六项任务信息组成完整横向信息栏。移除额外介绍、大块方向概要和单独操作行；刷新、重试与追加移入所属主体面板标题，学习历史使用现有顶栏入口。文本左侧协作轨迹约30%宽，使用两个真实阶段节点/连线及分层资源条目，右侧资源预览约70%宽；手机自然堆叠。使用深蓝按钮、青色语义状态与细分隔线，把宽高留给主体，两个面板标题对齐。预览正文去掉重复阅读器头部，等级与下载合并至资源选择器工具栏；“学习模式”在最右侧，与上方“追加资源”同宽/右对齐，正文独立滚动。默认学习页仍保留阅读器原头部和Tutor操作；下载函数与等级映射由同一阅读器实现复用。状态来自真实任务/连接/发布记录；失败理由、单资源重试、审核报告、追加文本/课件和学习入口保留，新增界面不修改生成、Claim 或课件发布契约。
- 桌面宽≥1100px、高≥640px且固定内容完整容纳、阅读/过程区域各至少120px时固定框架；两个正文区独立滚动并阻止边缘滚动传出，选择器和标题保持可见。窗口、侧栏、任务/资源变化会重测，切换后所属正文回顶。窄屏、极短窗口、长固定内容或文本与课件 composer 同时存在时回退自然阅读；课件保留既有过程/详情及内部滚动。追加和审核弹窗正文可滚动，主要操作至少44px，键盘焦点可见并支持减少动态效果。

推荐交互方式如下：

```text
用户点击“生成”
-> 页面提示“资源正在生成”
-> 从持久化 timeline 恢复，订阅 WorkflowEvent SSE；连接错误后降级为任务 / timeline 轮询
-> 生成/审核高层节点可展开查看各资源状态
-> 任一资源批准后立即出现在资源库
-> 默认定位当前生成任务
-> 用户可切换查看历史成功任务
-> 在任务内选择资源阅读或下载
```

这也是当前文档和接口设计默认支持的前端模式。

各类文本资源阅读页均显示经审核的 Markdown 文本。草稿、返工、拒绝和人工审核资源均不可预览。

### 6.4 学习资源与专注阅读

- 初次载入和没有可读产物时，用学习工作区准备画面解释路径：上部组织真实状态说明与静态学习流程示意，下部以连续三分区介绍阅读、实践、复盘能力，操作区在桌面可用高度内收尾，窄屏自然堆叠。根据实际画像、加载与当前生成任务数据区分尚未建立方向、排队/生成中、失败及暂无发布材料，沿用原生成和新建方向入口；仅在实际读取中显示忙状态，尚未成功载入时提供中性说明及刷新途径。流程图和能力说明不表示已有资源或实时进度，有已发布资源后恢复正常资源架与阅读正文。
- `/resources` 保持画像/批次工具栏、横向资源切换、整宽阅读正文及原 Tutor 面板的主要结构；顶栏沿用工作台/新建方向/资源生成页的紧凑标题、辅助入口及用户信息布局，释放正文空间。视觉使用雾白底、深蓝文字、青色细节和较小圆角；当前资源以浅青底、青色细描边/标记和深色文字区分，普通与专注模式保持一致。反馈测评使用青色强调，下载为描边次操作，Tutor 为深蓝主操作。工具栏、下载、Tutor 和专注模式按钮点击高度至少44px，悬停与键盘焦点清楚；文档标题、正文、代码和关联知识点使用一致的阅读层次。
- 专注模式沿用原全高阅读、资源切换和退出方式，Tutor 保持原侧面板/窄屏覆盖模式。窄屏工具栏与阅读头部可换行，资源架继续独立横向滚动；支持减少动态效果。样式由学习页局部作用域及该页存在时的外壳选择器限定，生成页阅读工具条和其他页面不受此配色覆盖。

### 6.5 学习反馈与测评回顾

- 尚无实际测评题时显示对齐的“测评准备＋反馈说明”：使用等宽两栏和同构介绍、三行要点、底部说明，标题、图标、要点和页脚在桌面对齐；横线及底线均从文本列开始，与编号连接路径分开。左侧不再重复上方的方向与材料信息，右侧介绍学习体验的记录内容。初始状态显示“测评待开始”；点击原开始测评按钮并加载题目后，再展开原反思字段与提交入口，保持原默认值、作答门槛及提交语义。
- `/feedback` 沿用学习工作区的紧凑顶栏、雾白底、深蓝文字与青色细节；画像和批次工具栏使用 `PROFILE`、`BATCH` 英文辅助标识，与顶栏保留间距。桌面保持左侧测评、右侧学习感受，窄屏顺序排列；题目用编号与分隔线组织，单选、多选及后续学习节点使用浅青选中态。
- 反馈结果按学习回顾、得分指标、逐题结果及下一步方案分层展示；开始测评与生成资源使用深蓝主按钮，提交反馈使用浅青强调，提示和报告使用描边次按钮。主要按钮及答案选项点击高度至少 44px，保留禁用、提交中、成功与失败反馈，支持键盘焦点和减少动态效果。测评、Tutor、反思、提交及下一步确认沿用原请求与状态逻辑；浏览器专项以隔离 fixture 验证布局与交互，不调用实际模型。

### 6.6 画像请求归属与学习报告

- 历史、报告、资源生成和资源列表只呈现当前选中画像及报告时间窗口对应的数据。切换画像/窗口后旧数据与旧更新流失效；迟到的列表、分页、报告、资源详情、SSE 回调或轮询响应不会覆盖当前上下文。读取失败明确显示错误并提供重试，失败状态不把其他画像或时间范围的数据呈现为当前结果。

- 文本生成通过 FastAPI `BackgroundTasks` 执行；没有外部消息队列、文本任务取消或中断后的自动续跑。失败资源可通过批次 continuation 创建新 Run 重试。
- 互动课件使用持久化 outbox 和独立 Worker，提供任务重试、取消及 checkpoint 恢复；这些能力不代表文本任务已具备同样语义。
- 旧 P0-09 runtime 脚本仍引用迁移前的前端文件，并按旧反馈 / 报告字段静态判定；当前会在读取文件时失败，不能作为前端缺少功能的证据。
- 正式比赛质量、真实用户效果、CI 与目标部署放行需各自的执行证据。

## 9. 当前阶段结论

截至 2026-10-09 按当前源码核对，系统包含以下业务闭环：

- 可以注册、登录并维护本人资料
- 可以提交问卷并生成初始画像
- 可以进入诊断
- 可以发起异步资源生成任务
- 可以查询和下载生成资源
- 可以从历史时间线查看学习过程
- 可以通过 SSE 观察并断线续传持久化 WorkflowEvent
- 可以回放 Evidence、审核版本、Claim 判定和反馈后的画像/路径变化
- 可以在五步引导中确认资源，生成独立互动课件，并在报告中查看规范掌握度与路径

功能存在、隔离 fixture 验收、真实后端联调、模型质量与部署证据分别记录。当前工程入口是统一 acceptance；旧 P0-09 runtime 的路径和静态判定需先修复，正式演示再按 Runbook 核对数据库迁移、来源、反馈与报告。真实样本和独立评测不足时保留 `NOT_MEASURABLE`。

## 10. 审核返工、版本与发布能力

当前资源生成闭环在异步任务之内提供以下可靠能力：

- Reviewer 输出 approve、revise、reject、human_review 四类决策。
- 问题和返工要求采用结构化 code、severity、目标资源、action 与 priority。
- Generator 只修改指令命中的资源类型；返工提示同时携带上一版本原文和结构化指令，每次返工创建新 resource_id/version 并连接 parent_resource_id。
- 每轮资源和审核均可从 Run 时间线回放，旧版本不会被 WorkflowState 覆盖后丢失。
- 草稿、旧版本、返工、拒绝和人工审核资源保留用于审计，但不进入学习者默认资源库。
- 只有最终审核通过的当前叶子版本可下载。
- 混合检索和 Rerank 的结果仍需通过 KB、Chunk 版本与内容哈希验证后才能用于生成。

## 11. Claim 级知识溯源与评测（P0-06）

- 独立 Claim Extractor 不依赖 Generator 自报，按资源版本生成稳定 `clm_*` ID。
- Claim Judge 只允许使用当前 Run 已冻结的 Evidence；跨 Run、未知或伪造 ID 会拒绝。
- 支持 `supported`、`contradicted`、`not_in_evidence`、`non_factual` 四类判定。
- 完整 Claim 审核且存在无证据事实时，事实通过率达到配置阈值后进入用户审核报告；用户明确同意后才发布，contradicted 始终阻断。
- `claim_max_iterations` 默认 `0`；显式开启返工额度后，问题 Claim 才会生成带 `target_claim_ids` 的定向指令，新版本重新抽取和判定。
- 显式 `CLAIM_PARTIAL_PUBLISH=true` 可按策略发布符合条件的审核不完整资源，但保留 `incomplete` 指标，不计为完整 Claim 审核通过。
- Run 回放只记录 Claim ID、数量、判定计数和指标；全文通过专用 Claims 接口查询。
- 比赛幻觉率按最终发布叶子版本做事实 Claim 微平均；覆盖率仅认绑定稳定技能节点且
  判为 supported 的事实 Claim。
- 难度适配评测要求固定 `fixture_version` 金标，输出准确率和混淆矩阵；不把 Reviewer
  自评分当作金标。

## 12. 反馈后画像与学习路径闭环（P0-07）

- 正式入口为 `POST /api/feedback/attempts/run/submit` 和 `/api/feedback/attempts/batch/submit`；旧聚合分数 `/api/feedback/attempts` 返回 422 `FEEDBACK_EVIDENCE_UNVERIFIED`，旧 `/api/feedback/` 写入已移除。
- 总分由后端按逐知识点题数加权重算，边界为 `<0.60 remediate`、`0.60~<0.80 practice`、`>=0.80 advance`，任一知识点低于 0.60 会阻止整体进阶。
- 一次本地事务写入 Attempt、Decision、知识状态变更、画像 N+1 和路径 mutation。
- 低分默认推荐“降阶学习”补基础：从本轮资源真实目标递归回溯所有未掌握的同阶或低阶前置节点，并说明优先顺序；选择同阶前置节点保持当前阶，只有确认低阶节点才降阶。中分默认推荐纠错包但仍开放用户自选可学习节点，高分默认进入进阶学习（优先一旧一新；无旧节点时默认一个新节点，也可改选两个）；纠错包对正式测评未满分的结果可选，满分时不显示。确认纠错包后固定同时追加一份同批次的新分阶测评题，题干不得与本次历史测评完全相同，用于学习后的重新验证。
- 反馈报告先返回候选；学习者通过 `/api/feedback/followups/select` 确认后，`GenerationJobService` 创建真实异步任务。父子 Run 可追溯，失败状态与反馈成功状态分离。
- 未选择的反馈方案可在以后重新进入反馈报告时再确认；页面刷新或推荐快照变化不会使其失效，确认时仍执行知识库、先修和学习阶校验。
- Report 读取持久化掌握度、最近 Attempt、画像版本和当前路径；已有服务端判分的正式 Attempt 即可形成报告结论，不依赖下一轮资源方案是否已确认；重启后不回退。

## 13. WorkflowEvent SSE 与 Agent 实时轨迹（P0-08）

- `GET /api/runs/{run_id}/events` 将已提交的 WorkflowEvent 以 snapshot + replay + live tail 形式输出。
- 浏览器断线通过 Last-Event-ID 补齐缺失事件，前端 reducer 按 sequence/event ID 去重，不产生重复 Agent Step。
- 生成页以 SSE 为实时主通道；连续传输错误后才启用现有 Job/timeline 轮询，不同时高频运行两套机制。
- 页面刷新从 local run_id、Job 和持久化 timeline 恢复，再从最后 sequence 继续订阅。
- Agent 轨迹展示 running/success/degraded/failed/human_review/skipped、耗时、重试、Evidence/Claim 计数和返工轮次。
- P0-07 follow-up event 可跳转并订阅 child Run；不创建跨 Run 全局合并流。
- Evidence/Claim/资源正文仍使用专用详情 API，SSE 不暴露内部推理或大对象。

## 14. P0-09 比赛验收边界

- `p0-09-demo-suite/v1` 固定 KB、稳定 DocumentVersion/Chunk/knowledge point，以及三档 learner、Attempt、Review、Claim、SSE 和 failure injection。
- acceptance runner 分开执行 deterministic offline、local runtime 与显式 opt-in live smoke，manifest 不保存 Key、Prompt、模型原始响应或完整画像。
- 比赛方案数值阈值为幻觉率 `<5%`、难度适配准确率 `>=85%`、核心知识点覆盖率 `>=90%`；正式口径不用 Reviewer 自评分。
- P0-09 fixture 只有 3 个 learner，仅作管线校验；比赛口径的样本量由 14.1 的金标套件满足。
- SQLite 外键 hook、资源版本唯一约束和迁移演练脚本已存在。旧 runtime Gate 的前端文件路径与静态合同已滞后，当前不能完成有效检查；公共 health ready、隔离浏览器或本地源码核对均不能替代目标环境比赛 Gate。

## 14.1 比赛金标评测套件（RAG 工程领域）

- 套件位于 `backend/tests/fixtures/competition/`：`suite.json`（阈值与标注协议）、`profiles/`（3 背景 × 3 水平 × 2 目标节点 = 18 个画像）、`cases/`（18 画像 × 3 资源类型 = 54 组用例，满足比赛至少 50 组）、`claims/`（74 条事实 Claim + 4 条非事实 Claim，13 个能力节点全覆盖）。
- 学习者背景覆盖应届学生、转岗后端工程师、数据工程师三类画像；`expected_difficulty` 按套件内声明的标注协议生成（含 ml_basics 背景 tier1 提级规则），`predicted_difficulty` 由系统策略 `difficulty_for_tier` 计算。
- 评测服务 `app/services/reports/competition_suite.py` 复用 `compute_competition_claim_metrics` 与 `evaluate_difficulty_fixtures`：幻觉率口径为最终发布叶子资源上事实 Claim 的 `(contradicted + not_in_evidence) / factual_total`，难度适配输出准确率与混淆矩阵，覆盖率统计被 supported Claim 覆盖的目标节点比例。
- 离线执行入口 `backend/scripts/competition_eval.py`：不调用大模型，金标 Claim verdict 为已有人工整理标注；离线基线为幻觉率3/74≈4.1%、难度适配48/54≈88.9%、覆盖率13/13=100%。这些是数据/策略回归数值，`gates` PASS 不表示真实生成达标；报告 `completed_generation_count=0`，`official_gates` 均为 `NOT_MEASURABLE`，独立质量复核未运行。
- Live 评测通路已实现，但本轮未执行真实模型：生产生成/Claim审核后记录每例输入、run_id、事件hash、来源快照、Claim与资源hash；异常记安全类型与失败阶段并继续，失败保留在难度分母。要求显式开关/有效凭据/隔离环境；未就绪退出2。至少50完整完成、三背景/三类型、冻结来源与完整事实判定才可给运行指标结论，小样本为 `NOT_MEASURABLE`，失败退出1。系统自审仍不替代独立质量复核；`--require-official` 在缺正式证据时退出2。
- 回归入口：`backend/tests/unit/reports/test_competition_suite.py`（结构、标注协议与 live 计划映射校验）、`backend/tests/integration/workflow/test_competition_metrics.py`（三项指标与混淆矩阵端到端）与 `backend/tests/live/test_competition_live.py`（live 就绪门禁与小批量真实执行，默认跳过）。
- 领域泛化与可迁移能力有可执行证明：评测代码不绑定任何领域特定逻辑，`load_suite`/`validate_suite`/`evaluate_competition_metrics` 支持注入领域套件自身的 suite_id 与知识库根目录；`test_evaluation_pipeline_transfers_to_new_domain_without_code_changes` 用合成第二领域（仅新增数据文件：知识库 manifest + 套件四文件）跑通加载、校验与三项指标计算全链路，证明迁移到新领域零代码改动。
- 来源快照冻结现有KB的10份文件与51个证据章节，按UTF-8/LF hash校验，引用/版本/正文漂移拒绝加载；本地模块附论文/官方文档来源，但未认证在线核验或独立专家复核。54例通过实际工作流/Claim/发布控制配合 Scripted Agent 回放，报告完整输入/trace/最终资源，明确 `live_generation_count=0`。
- 完整层级、功能映射与报告规范见 [测试方案](testing/README.md)，比赛数据/指标/正式证据流程见 [比赛评测方案](testing/competition.md)。统一 `scripts/run_tests.py` 提供 quick/regression/acceptance 与领域专项，当前登记 8 个前端单元专项和 13 个浏览器专项，保留原入口；必需浏览器不能以缺环境冒充通过，CI 复用同一目录并保留课件硬门与手动 live 边界。

## 15. 证据约束 Tutor 导学

- 已发布资源页提供“向 Tutor 提问”，测评页每题提供“需要提示”；抽屉支持活动会话恢复、多轮求助、loading/error 状态和引用展示。
- 提示阶段由服务端确定性策略控制：首次求助为方向提示，明确继续困惑时升级为结构化拆解，第三轮及以后才允许完整的 grounded explanation。
- Tutor 只使用题目对应真实 Run 的 Frozen Evidence、兼容 SourceRef 或 Ready 知识库上的受控检索；无证据时 fail closed，不使用模型常识兜底。
- Tutor 不修改画像、Mastery、LearningPath 或 Resource。批次测评提交时，服务端按 `batch_id` 汇总持久化的题目求助轮次并映射到现有 Attempt `hint_count` 审计字段；旧 Run 调用保持兼容。
- 会话与轮次具备访问控制、唯一序列、`client_message_id` 幂等、引用子集校验和脱敏 LLM 遥测。
## 16. 分阶能力节点学习闭环

- 能力节点支持统一三阶等级、学习者起始阶级、自评准入豁免、同阶最多三节点推荐、低分降阶补前置节点、中分补弱和高分解锁/升阶。
- 节点目标、资源难度和发布审核采用同一服务端阶级契约；不允许混阶目标或用高阶节点补足批次。
## 17. 复习清单 V2 互动课件

已发布的 V2 主动回忆复习清单可沿用既有互动课件工作流生成 HTML 课件。课件固定呈现总览、每能力节点的闭卷回忆/概念辨析/正反例三页及总结页；题目与答案来自冻结的结构化 payload，答案默认隐藏。学习者的“会/模糊/不会”仅形成低置信度自评，不作为正式测评成绩。
