# 功能文档

> 项目编号：XH-202630  
> 项目名称：领域知识个性化生成与多智能体协同决策系统  
> 文档版本：v1.1  
> 文档定位：描述系统功能范围、核心流程、功能模块和用户侧能力，不承担任务分工职责。

## 使用原则

本文档描述的是功能基线，用于说明系统要实现哪些能力，不是限制后续实现方式的固定合同。并行开发中可以根据比赛要求、技术验证结果和实际实现进度，对功能拆分、交互形式或具体实现细节进行调整，只要不改变系统核心目标和用户侧能力方向即可。

本文档只保留基础功能与能力边界，具体代码实现可以修改、替换或重构；若功能范围有变化，优先更新相关接口文档和架构文档。

## 2. 系统功能概览

系统围绕“领域知识个性化生成”和“多智能体协同决策”构建闭环能力：

```text
学习者画像
  -> 学情诊断
  -> 知识库检索
  -> 个性化资源生成
  -> 审核纠偏
  -> 决策输出
  -> 学习反馈
  -> 画像更新与迭代
```

## 4. 核心流程

### 4.1 资源生成流程

```text
输入学习者画像与学习主题
  -> 学情诊断：识别能力标签、弱点、推荐难度
  -> 知识检索：从领域知识库召回相关片段
  -> 内容生成：生成讲义、实操指南、测试题
  -> 审核纠偏：检查事实准确性、难度匹配、知识覆盖
  -> 决策输出：通过、重生成或带风险提示输出
  -> 持久化：保存资源、来源引用和执行轨迹
```

### 4.2 反馈迭代流程

```text
从生成资源中选择分阶测试题
  -> 提交答题结果
  -> 计算正确率
  -> 决策判断
  -> 更新学习者画像
  -> 触发下一轮资源生成建议
```

说明：测试题属于资源生成结果的一种，通常由资源生成流程在 `resource_types` 包含 `分阶测试题` 时产出。反馈流程通过测试题资源的 `resource_id` 关联答题结果。

| 正确率 | 决策 | 功能含义 |
|--------|------|----------|
| `< 60%` | 降维解释 | 降低难度，补充基础解释 |
| `60% - 85%` | 保持当前难度 | 继续巩固当前阶段 |
| `> 85%` | 进阶挑战任务 | 提升难度，推荐更高阶任务 |

### 4.3 知识库处理流程

```text
原始文档
  -> 元数据读取
  -> 文档切片
  -> Embedding 向量化
  -> 写入 ChromaDB
  -> 语义检索
  -> 返回知识片段和来源引用
```

## 5. 功能模块说明

### 5.1 学习者画像

学习者画像用于支撑个性化诊断、资源难度匹配和学习路径推荐。

| 字段 | 说明 |
|------|------|
| `learner_id` | 学习者唯一标识 |
| `education` | 学历背景 |
| `major` | 专业方向 |
| `theory_scores` | 各知识点理论得分 |
| `skill_level` | 当前技能水平 |
| `weak_points` | 知识盲区 |
| `strong_points` | 优势领域 |
| `learning_goal` | 学习目标 |

### 5.2 多智能体协同

| Agent | 功能定位 | 输入 | 输出 |
|-------|----------|------|------|
| 学情诊断 Agent | 分析画像并推荐学习策略 | 画像、主题 | 能力标签、弱点、推荐难度 |
| 知识检索 Agent | 检索相关知识片段 | 主题、弱点 | 知识片段、来源、相似度 |
| 内容生成 Agent | 生成个性化学习资源 | 画像、知识片段、资源类型 | 讲义、实操指南、测试题 |
| 审核纠偏 Agent | 检查内容质量和幻觉风险 | 生成内容、知识片段 | 审核结果、幻觉分、覆盖率 |
| 决策 Agent | 综合判断输出结果 | 生成结果、审核结果 | 最终决策、重生成建议 |

### 5.3 幻觉防控

系统采用三层防控机制：

| 层级 | 机制 | 功能要求 |
|------|------|----------|
| 知识约束 | 生成时注入 RAG 检索片段 | 内容应基于知识库材料生成 |
| 交叉验证 | 审核 Agent 检查生成结果 | 识别事实错误、步骤错误、难度不匹配 |
| 知识溯源 | 输出来源文档和相似度 | 用户可追踪生成内容依据 |

### 5.4 资源生成

资源类型以教学场景为核心：

| 资源类型 | 内容要求 |
|----------|----------|
| 讲义 | 结构化概念解释、关键知识点、示例说明 |
| 实操指南 | 操作步骤、注意事项、常见错误 |
| 分阶测试题 | 基础题、进阶题、答案或解析；作为后续学习反馈的数据来源 |

生成结果需要包含：

- `resource_id`
- `resource_type`
- `difficulty`
- `content_text` 或 `file_path`
- `knowledge_points`
- `source_refs`

### 5.5 学情报告

学情报告用于帮助用户理解当前能力状态和下一步学习方向。

| 报告模块 | 功能说明 |
|----------|----------|
| 能力雷达图 | 展示各知识点掌握程度 |
| 知识盲区 | 展示低分或薄弱知识点 |
| 难度曲线 | 展示得分与推荐难度关系 |
| 学习路径 | 按弱点、目标和难度生成学习顺序 |

### 5.6 前端页面能力

以下页面是功能基线，不代表当前前端代码都已经提供对应路由；实际建设状态以 `docs/task-allocation.md` 和代码为准。

| 页面 | 路由 | 功能说明 |
|------|------|----------|
| 首页 | `/` | 系统入口、功能导航、概览展示 |
| 学习者画像页 | `/learner` | 录入和查看学习者画像 |
| 资源生成页 | `/generate` | 提交主题、触发生成、展示资源和 Agent 轨迹 |
| 学习反馈页 | `/feedback` | 提交答题结果、展示反馈决策 |
| 学情报告页 | `/report` | 展示雷达图、难度曲线、学习路径 |
| 资源库页 | `/resources` | 查看历史生成资源、下载文件资源 |

### 5.7 测试与演示能力

功能测试应覆盖核心闭环：

| 场景 | 验证目标 |
|------|----------|
| 画像创建 | 画像字段校验和保存正常 |
| 资源生成 | 能返回资源、执行轨迹、审核报告 |
| 反馈迭代 | 正确率能触发对应决策 |
| 报告展示 | 雷达图、弱点、路径和难度曲线数据完整 |
| 知识溯源 | 生成内容包含来源文档和知识片段 |

## 7. 非功能指标

| 指标 | 目标 |
|------|------|
| 专业知识幻觉率 | `< 5%` |
| 画像与资源难度适配准确率 | `>= 85%` |
| 核心知识点覆盖率 | `>= 90%` |
| 单次生成响应时间 | `< 30s` |
| 生成结果可追溯性 | 资源应包含来源引用 |
