# 项目扩展思路

本目录保存已选定的项目升级方向。每项方案都先核对当前源码，再说明缺点、接入位置、兼容约束、成本与验收要求；不把尚未验证的收益写成已经实现的效果。

这些文档是方向依据，不自动授权业务实现。正式实施按[仓库约束](../../AGENTS.md)在 `docs/update_plan/` 建立或修订计划，通过门禁后执行。

## 三项方案共同遵守的边界

- 在现有目录、契约与工作流中升级，不更换检索框架、不另建生成系统或人工审批工作台；必要的输入、字段和校验改动应在实施计划中列明。
- 保留当前公开入口限制：普通生成请求最多 2 个目标节点；启用 Claim 时要求普通审核开启且单请求仅一种资源。目录中的方向不构成放宽这些限制的授权。
- E1 通过现有策略回退和关闭增强控制风险；E2 保持原数量、修订预算与发布条件；E3 保留来源、安全、必需内容和幂等发布硬门，审核不可用不能冒充通过。
- 可用性验收同时检查正确任务完成率、误拒、质量、时延和成本。源码核对仅证明接入依据，不等于实际可用性或降幻觉效果已经通过验证。
- 每项实现按对应范围运行仓库要求的回归；涉及共享后端时执行后端全量，课件还需冻结评测和浏览器验证。真实模型评测按明确授权执行。

## 文档约定

- 文件命名为 `E<N>-<主题英文短名>.md`。后续新增取本目录已有最大数字加一；同一方向修订沿用文件。
- 每个方向给出一条明确方案和连续步骤，写清已有能力、拟新增能力与不纳入本次的事项，不留互斥路线让实施者自行二选一。
- 历史测试注明日期、证据位置和适用范围；不能以历史局部测试代替未来实现的回归，也不能以程序测试证明真实模型效果。
- 按实际改动同步路径、交叉引用与状态；保留已有实现、历史产物及其他工作树修改。
