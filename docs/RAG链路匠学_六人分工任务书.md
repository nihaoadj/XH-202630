# RAG 链路匠学六人分工任务书

项目定位：

**RAG 链路匠学是面向大模型应用开发学习者的多智能体个性化 RAG 工程训练系统。**

系统核心闭环：

```text
学习者画像输入
→ RAG 能力诊断
→ 多智能体协同决策
→ 个性化学习资源生成
→ 审核纠偏与知识溯源
→ 学情报告与可视化
→ 学习反馈
→ 动态调整学习路径
```

---

## 一、必须完成的核心模块

以下功能属于 **P0 必须完成模块**，缺少其中任意一项，作品容易退化成普通 RAG 问答系统。

1. **RAG 链路能力图谱**
   - 文档解析
   - Chunk 切分
   - Embedding
   - 向量数据库
   - 检索策略
   - Rerank
   - Prompt 组装
   - 引用溯源
   - 幻觉控制
   - RAG 评测与调优

2. **学习者画像与能力诊断**
   - 至少支持 3 类学习者：
     - 零基础学生
     - 有 Python 基础学生
     - 进阶 RAG 学生
   - 输出学习者能力等级、知识盲区、推荐学习路径。

3. **多智能体协同闭环**
   - 至少实现 5 个 Agent：
     - 学情诊断 Agent
     - RAG 专家检索 Agent
     - 学习路径规划 Agent
     - 个性化资源生成 Agent
     - 审核纠偏 Agent
   - 建议增加：
     - 反馈决策 Agent

4. **个性化资源生成**
   - 至少生成 3 类资源：
     - 定制讲义
     - 实操指南
     - 分阶测试题
   - 建议增加：
     - 学习路径卡片
     - RAG 调优报告

5. **审核纠偏与知识溯源**
   - 生成内容必须绑定知识库证据。
   - 实现 claim 级审核。
   - 输出幻觉率、审核通过率、纠错记录。

6. **动态反馈机制**
   - 根据答题结果或实操表现调整学习路径。
   - 支持降维解释、针对性补救、进阶挑战。

7. **可视化报告**
   - RAG 能力雷达图
   - 知识盲区热力图
   - 学习路径图
   - Agent 协同流程图
   - 资源难度匹配结果

8. **量化评测**
   - 幻觉率
   - 知识点覆盖率
   - 难度适配准确率
   - 检索命中率
   - 反馈后提升率

## 三、成员 2：多智能体开发负责人

角色定位：

负责系统最核心的多 Agent 协同决策、调度流程、生成逻辑和审核纠偏机制。

主要负责目录 / 文件：

- `backend/app/agents/`
- `backend/app/services/generation_service.py`
- `backend/app/services/feedback_service.py`
- `backend/app/core/llm.py`
- `backend/app/core/knowledge_base.py`（调用知识库能力）
- `backend/tests/`

### 短期任务：第 1-2 周

必须完成：

- Agent 角色设计。
- Agent 输入输出格式。
- Agent 调度顺序。
- `agent_orchestrator` 核心流程草案。

至少实现 5 个 Agent 的职责定义：⭐

1. **学情诊断 Agent**
   - 输入学习者画像和诊断测试结果。
   - 输出薄弱知识点、能力等级、学习目标。

2. **RAG 专家检索 Agent**
   - 从 RAG 知识库检索证据。
   - 输出带来源的知识片段。

3. **学习路径规划 Agent**
   - 决定学习者先学什么、跳过什么、补什么。
   - 输出学习路径和资源生成要求。

4. **个性化资源生成 Agent**
   - 生成定制讲义、实操指南、分阶测试题。

5. **审核纠偏 Agent**
   - 检查生成内容是否准确。
   - 判断内容是否有知识库证据。
   - 判断难度是否匹配学习者画像。

建议增加：

6. **反馈决策 Agent**
   - 根据答题正确率和实操结果决定降维解释、补救学习或进阶挑战。

### 中期任务：第 3-4 周

必须完成：

- 多 Agent 编排器。
- 一次完整 Agent 协同闭环。
- Agent 中间结果保存。
- Agent 过程可视化所需数据接口。

每次 Agent 运行必须保存：

- 每个 Agent 的输入。
- 每个 Agent 的输出。
- 决策理由。
- 检索证据。
- 审核结论。
- 修改记录。
- 最终资源。

核心流程必须跑通：⭐

```text
画像输入
→ 学情诊断 Agent
→ RAG 专家检索 Agent
→ 学习路径规划 Agent
→ 个性化资源生成 Agent
→ 审核纠偏 Agent
→ 最终资源输出
```

### 长期任务：第 5 周到提交前

必须完成：

- Claim 级审核机制。
- 审核纠偏闭环。
- 幻觉率计算。
- Agent 协同过程稳定展示。

Claim 级审核流程：⭐(学姐项目里面有类似的好像)

```text
生成学习资源
→ 抽取关键知识 claim
→ 检索知识库证据
→ 判断 claim 是否被证据支持
→ 不支持则退回重写
→ 输出可信度评分
```

输出指标：

- claim 总数。
- 有证据支持数。
- 无证据支持数。
- 疑似幻觉数。
- 幻觉率。
- 审核修正次数。

### 创新点责任

多智能体开发负责人主打以下创新：

1. 多 Agent 角色制衡。
2. 生成 Agent 与审核 Agent 对抗式协作。
3. Claim 级溯源审核。
4. 幻觉率可量化。
5. 多 Agent 中间决策过程可解释。

## 八、项目核心创新点总结

最终申报材料建议主打以下 5 个创新点。

### 创新点 1：RAG 链路能力图谱

将 RAG 工程能力拆解为可诊断、可训练、可评测的知识技能节点，覆盖文档解析、Chunk、Embedding、检索、Rerank、Prompt、溯源、评测和调优。

价值：

- 避免泛泛教学。
- 让学习者短板可定位。
- 让资源生成有明确依据。

### 创新点 2：学习者画像驱动的个性化资源生成

系统根据学习者背景、测试结果、知识点掌握度和学习目标，生成不同难度、不同形态的学习资源。

价值：

- 零基础学生获得降维解释。
- 有 Python 基础学生获得实操任务。
- 进阶学生获得调优挑战。

### 创新点 3：多智能体协同决策机制

通过学情诊断 Agent、RAG 专家检索 Agent、学习路径规划 Agent、资源生成 Agent、审核纠偏 Agent 和反馈决策 Agent 协同完成训练闭环。

价值：

- 将“生成内容”升级为“协同决策”。
- 让系统不再是单模型直接输出。
- 更符合赛题多 Agent 要求。

### 创新点 4：Claim 级知识溯源与幻觉防控

系统将生成内容拆分为关键知识 claim，并为每条 claim 绑定知识库证据，由审核 Agent 判断是否支持。

价值：

- 幻觉可发现。
- 错误可纠正。
- 可信度可量化。

建议指标：

- claim 总数。
- 有证据支持数。
- 无证据支持数。
- 幻觉率。
- 审核修正次数。

### 创新点 5：实操反馈驱动的动态学习路径调整

系统根据学习者答题结果、实操表现和反馈信息，自动调整后续学习资源。

反馈策略示例：

- 正确率 <60%：降维解释，补前置知识。
- 正确率 60%-85%：生成针对性练习。
- 正确率 >85%：生成进阶挑战。
- 连续答错同一知识点：回退到前置节点。

价值：

- 形成完整学习闭环。
- 体现动态决策。
- 提升实用价值。
