# 真实测试记录

每次真实测试在本目录新建 `E<N>/`，编号按现有最大数字加一，无则从 `E1` 开始，不覆盖旧目录。复验使用新编号，报告注明前次编号；失败、中断和预检阻塞也保留。

唯一必需文件是 `report.md`：

```text
docs/evaluations/
  E1/
    report.md
  E2/
    report.md
```

报告简要记录：测试目的与日期、实际入口/配置/命令、run_id（如有）、预期与实际结果、结论和未覆盖项。可参考[简短模板](templates/report.md)，不重复填写清单或索引。

## 调用用量与计费（每份真实报告必填）

报告必须有“调用用量与计费”说明，失败、中断、未进入模型的测试也不省略：

- **调用口径**：分别记录逻辑调用数与 gateway attempts；不能混为同一个“调用次数”，也不能将 attempts 直接等同供应商实际处理/扣费次数。注明统计来源及是否完整。
- **可计费用量**：列出输入、输出 token；供应商区分缓存命中/未命中、推理或其他计费项时分别记录，并说明是否已包含在输入/输出中，避免重复相加。只有总 token 时明确缺少拆分，不按总量随意套用输入单价。
- **价格依据**：注明实际供应商/平台、模型及版本、计费档位、币种、输入/输出及其他适用单价和计价单位，附价格来源、核实日期与适用日期。不能把其他平台同名模型价格直接套用，也不能把配置里的历史单价称为当前官方价。
- **金额与算法**：可计算时给出“各计费项用量 × 对应单价”的明细和合计。分别标明费用估算、供应商账单实际金额、实际现金扣款；无账单证据不得写“实际扣费”。折扣、免费额度、缓存优惠或阶梯价格只在有依据时应用。
- **完整性与范围**：包含本任务的失败尝试、重试、普通返工和Claim返工，不只统计最终成功调用。说明漏记、未知usage、超时或未结算项是否可能产生费用，估算是否仅覆盖已知部分。复验报告列明本次金额及所关联测试累计金额；缺少依据时分别标未知，不把不完整金额当完整累计成本。
- **未知与零**：价格、用量拆分或账单不足时，明确写“费用未知/暂不可计算”及原因、已有数据和缺失项，不能只列token后省略费用结论。仅在确证未发生模型调用时可写“已确认模型调用用量为0，按调用产生的模型费用为0”；其他存储、检索、运行等成本是否纳入另行说明。零已知用量不能代表超时请求无费用。

要求仅增加报告内容，不强制增加JSON、清单或新目录；不得为补计费数据追加模型调用、打印凭据或未经授权操作外部账单账户。历史报告不批量重写，后续新测试及明确要求补充的报告按此执行。

日志、JSON、截图、产物等仅保存支撑结论的必要文件，直接放在同一编号目录并在报告中链接。不要求额外子目录、test.json、索引或校验清单，不复制大批无关输出；大型或受限文件可引用原路径并说明限制。

真实测试沿用当前授权范围，不因本规范额外执行调用或扩大次数；不保存凭据或敏感信息。纯离线/mock测试继续原测试目录。真实结果默认本地留存，不自动提交或上传；已有历史目录和记录不搬迁、不删除。

需要补充解释时参阅[执行说明](protocol.md)和[结果说明](data-contract.md)，普通测试无需逐份阅读。仅在明确要求对照评测时按需使用原有对照模板。收尾在对应更新计划中链接本次报告。
