# 互动 HTML 课件 3.0 升级任务书

> 文档用途：完整替代旧版课件体验质量任务书，作为后续实现与验收的唯一交接入口。
> 当前状态：`TASK_NOT_READY / QUALITY_PARTIAL`。旧任务阶段、完成状态和历史自报结果均不继承。
> 设计方向：桌面固定画布优先、编辑式数据叙事、结构化视觉组件、内容充实且可客观验收。

## 1. 目标与参考

本轮把互动课件从“基础可用的长页面卡片”升级为“占满学习区域的分页课程”。设计原则参考 H5P Course Presentation、Articulate Storyline 的分页课程与交互节奏，以及 Fluent 2 一类成熟设计系统的字体、颜色、间距和状态 token；只借鉴原则，不复制外部资产。

- 桌面端每页占满学习区域、位置固定，不出现页内上下滚动。
- 移动端优先可读性，允许有限纵向滚动，但禁止横向溢出和不可达操作。
- 每页有明确主题、信息架构和结论，不得出现空页、单句页或单卡片薄页。
- 课程使用受控信息图、流程图、对比矩阵、证据卡等平台组件提升复杂度和美观性。
- 模型只能生成版本化结构化契约，不得输出 HTML、CSS、JavaScript、SVG、URL 或任意视觉 token。

## 2. 不可破坏的边界

- 保留现有 HTTP 路径、认证、来源快照、字段级 provenance、安全硬门、CSP、发布幂等、Worker 恢复、current release 隔离及 HTML/ZIP/SCORM/xAPI 导出。
- 旧 1.0 课件继续读取；只有重新生成的 release 使用课件 3.0 视觉与页级契约。
- 平台拥有主题、版式、图标、动效和组件注册表；模型只可使用允许列表中的稳定 ID。
- 未知 recipe、未知组件、无来源事实、无来源答案和危险输出仍为发布硬门失败。
- 不接入外部图片服务。结构化图形由平台确定性渲染。
- 本地测试通过只证明定义的版式、完整度、响应式、可访问性和一致性门，不宣称机器证明“审美优秀”。

## 3. 固定画布与播放器

- `CoursewareViewer` 使用剩余学习区域的自适应高度，删除固定 `720px` iframe。
- HTML 舞台使用 `width:100%`、`height:100%`；第一场景显示完整封面，后续场景只显示紧凑课程栏、页码、章节导航和固定底部操作区。
- 桌面基准视口为 1280×720、1440×900、1920×1080，活动场景必须满足 `scrollHeight <= clientHeight + 1`，无水平滚动、文字裁切和控件遮挡，正文不小于 16px。
- 360px/768px 使用重排布局；移动端允许有限纵向滚动。
- 支持方向键、上一页/下一页、章节目录、全屏、重新开始和 release 级状态恢复。

## 4. 页级课程规划

新增向前兼容的版本化蓝图：

- `CoursewareLearningDesign` 支持 `3.0`；`StoryboardSpec`、`CoursewareSceneSpec` 支持 `2.0`。
- 页面固定描述 `page_role`、`layout_recipe_id`、`key_question`、`objective_ids`、`required_zones`、`content_budget`、`allowed_component_ids` 和冻结来源绑定。
- 页面角色限定为：封面、学习地图、概念解释、流程拆解、案例诊断、对比分析、实践工作台、知识检查、总结行动。
- 每份课件仅对应一份已发布源资源；讲义、实操指南、案例、复习清单和分阶测试题均可独立生成。
- 常规课件最多 24 页。实操指南例外：每个经来源校验的操作步骤必须独立成页，不得为了页数上限合并不同步骤。
- 每页必须回答一个明确问题，并形成“引导语 → 主体信息 → 证据/示例 → 页面结论”的闭环。

### 4.1 按资源类型编排

- 讲义是知识主线。按冻结来源块和 220–650 字内容预算切成连续学习阶段，每页只解决一个子主题，并明确与上一阶段、下一阶段的关系；禁止把整篇讲义压成一页，也禁止按固定页数机械切割。
- 实操指南先由 LLM 仅提取“步骤标题 + 冻结来源块 ID”结构；平台以源文档中显式的“步骤 N”标题锁定数量与顺序，并要求模型把每个标题至下一标题之间的语义块完整、无重叠地回链。遗漏、重复、越序、未知块或与锚点不一致时，不采纳模型分组，而是仅按显式标题确定性回退，绝不把普通段落、代码或清单项扩成新步骤。每个已验证步骤形成一页完整实践工作台：本步目标、源文本中的详细操作、完成校验、衔接提示和一个可键盘勾选的完成动作；单一步骤内容过密时，可在语义块边界拆成最多两页“说明 1/2、2/2”，仍算同一个步骤。
- 案例分析使用案例诊断版式，覆盖背景、问题、定位过程、证据和结论。
- 复习清单使用可勾选复盘工作台，呈现掌握状态和补学入口。
- 分阶测试题使用知识检查版式，必须展示错误原因和下一步建议；缺少可验证答案时省略，不得编造。

## 5. 内容复杂度与密度

- 普通内容页包含 2–4 个有效信息区和至少两个语义层级。
- 概念、案例、流程页目标为 220–650 个中文字符；封面、检查和总结使用专属预算。
- 每页至少覆盖解释、证据、流程、示例、对比、误区、操作、反馈、结论中的两个类型。
- 封面包含课程收益、知识范围、预计时长和学习路线；学习地图展示章节关系与完成路径。
- 案例页包含背景、问题、定位过程和结论；实践页包含目标、步骤、输入/输出和完成标准。
- 检查页包含错误原因与下一步建议；总结页包含目标完成状态、核心结论和后续行动。
- AI composer 按页级蓝图填充内容，不再把“最小合法模板”当作内容目标。
- deterministic fallback 同样生成多区块页面；来源不足时合并页面并记录降级，不发布空壳。

## 6. 设计系统 2.0

保留 `editorial`、`midnight`、`paper` 主题 ID，默认使用编辑式数据叙事风格。

- 使用 12 栏自适应网格、页级安全区、紧凑标题栏和固定导航区。
- token 覆盖背景层级、文字层级、强调色、语义色、间距、圆角、阴影、边框、图标、数据色板和密度档位。
- 注册九种平台版式：`editorial_cover`、`learning_map_grid`、`concept_split`、`process_lane`、`comparison_matrix`、`case_diagnostic`、`practice_workspace`、`quiz_focus`、`recap_dashboard`。
- 注册结构化视觉组件：指标条、流程图、概念关系图、证据卡、对比表、决策路径、代码/步骤面板和结论条。
- 图形只由平台使用受控 DOM/CSS/SVG 渲染；动效只服务于翻页、状态反馈和关系强调，并支持 reduced-motion。

## 7. 发布前质量硬门

- `EMPTY_PAGE`：无有效内容区或仅有标题。
- `THIN_PAGE`：内容区、字符量或信息层级低于页面角色门槛。
- `OVERFLOW_PAGE`：桌面视口出现滚动、裁切或越界。
- `UNDERFILLED_PAGE`：桌面主体区域使用高度低于 65%。
- `REPETITIVE_PAGE`：连续页面角色、组件组合或正文高度过度相似。
- `MISSING_PAGE_CONCLUSION`：普通内容页没有结论。
- `UNPLANNED_LAYOUT`：使用未注册 recipe。
- `UNSUPPORTED_VISUAL_PAYLOAD`：结构化图形数据不完整或无法追溯。

可修复问题进入最多两轮定向修订；仍失败则拆页、合并或阻止发布。不得把空页作为可接受降级。AI 审核负责内容完整度、解释深度、主题聚焦、跨页叙事、视觉信息结构和重复度；浏览器测量是像素级版式的最终裁决。

复杂课件采用“可靠性可降级、体验底线不可降级”的发布策略：AI 审核暂时不可用、非必需高级交互失败或个别可选资源无法采用时，可回退为已验证的确定性组件并带警告发布；空页、薄页、无来源内容、未知组件、桌面溢出、不可达操作以及讲义/实操主线缺失仍是硬门。美观度不以主观分数宣称，而由注册 recipe、主题 token、浏览器矩阵、占用率和一致性证据共同约束。

## 8. 固定实施顺序

```text
C0 冻结当前视觉与内容反例
→ C1 页级蓝图、内容预算与兼容契约
→ C2 去空页 storyboard 和丰富 fallback
→ C3 设计系统 2.0 与结构化视觉组件
→ C4 固定画布 renderer/runtime/player
→ C5 内容、重复与浏览器版式质量门
→ C6 冻结评测、完整回归和受限真实模型复验
```

每阶段必须先新增失败反例，再实现，再运行专项与上层回归；不得删除、跳过或放宽测试制造通过。

## 9. 测试与验收

- 契约：旧 1.0 可读；新版本拒绝未知页面角色、recipe、组件和无来源内容。
- 规划：5/15/30/60 分钟具有稳定页数和职责；来源不足时减少页数，不生成空页。
- 内容：每种页面角色满足区块、字符、结论和来源要求。
- Renderer：九种 recipe × 三主题确定性输出，事实和答案不随主题变化。
- 浏览器：九种 recipe × 三主题 × 360/768/1280×720/1440×900/1920×1080；检查滚动、裁切、占用率、字号、触控目标、对比度、焦点、200% zoom 和 reduced-motion。
- 用户截图回归：iframe 占满学习区；首屏无大段无意义空白；中间页不为空；桌面无需上下滚动；导航固定可达。
- 使用一套 8–10 页黄金 fixture 保存脱敏 computed evidence 和截图 hash，截图本身不提交。
- 依次运行课件单元、集成、e2e、浏览器专项、前端 build、冻结 evaluator 和完整后端回归。
- 离线门全部通过后，才运行一次受预算约束的真实模型矩阵，并分别报告 AI 完整生成、fallback、薄页修订、发布和失败数量。
